# RMUL 3V3 团队决策需求

版本：0.2.0；日期：2026-11-01。用户已确认赛项为 2027 高校联盟赛 3V3，并说明当前重装、步兵、哨兵均不能上高地或通过隧道。本文件由 AI 协助整理，策略参数和场地配置待队伍验收。

## 车辆能力与控制范围

当前三车不能上高地、不能通过隧道，是本队车辆能力约束，不是宣称赛事禁止这些通行方式。目标点在平地，并不代表到它的路线可用：规划路线若经过禁用地形，同样拒绝。

如果两处高地控制区因此不可达，哨兵就不能被分配去补这些点。可选任务只能来自已验证可达的中央控制区、地面防守/掩护岗位、补给路线和巡逻点。地图未完成标注前，不编造点位、不假定三点均可占领，也不声称算法能补足车辆通行能力。

程序只控制哨兵。重装和步兵由人控，队友血量和位置是观察输入，不是指挥权限。`coverage_requested` 只供本机检查/显示，不能理解成已通知队友、更不能理解成队友已承诺接替。实际赛场信息获取和显示必须遵守规则允许的链路；本包不创建队间通信链路。

## 先区分状态

| 状态 | 含义 | 处理原则 |
| --- | --- | --- |
| 低血 | 仍存活，血量低于进入恢复阈值 | 产生恢复需要，不能当成战亡 |
| 恢复中 | 已进入恢复过程，但未达到退出阈值 | 不因血量刚回升一点就视为可接替 |
| 战亡 | 有效血量为零 | 哨兵等待自动复活；不能安排移动/守点 |
| 虚弱 | 复活后尚未解除规则限制 | 哨兵回己方补给区，禁射、不占点 |
| 未知 | 数据过期、血量上限不明或规则状态未确认 | 不假定其健康、可接替或岗位无人 |
| 血量充足 | 有效状态已达到恢复标准且非虚弱 | 只说明血量条件；不证明有弹、能打赢或愿意接替 |

血量按各车自己的当前上限计算。重装不能统一套用哨兵的 400 血；装配造成性能变化时，需更新有效上限。初始策略使用低于 30% 进入恢复、达到 80% 退出；队友也保留恢复滞回，初次观察就在中间段时保守看作尚未完成恢复。数据掉帧不清除恢复记录。

## 八种血量组合

下表是假设三车均存活、非虚弱、状态可靠时的策略背景。“低”包括恢复尚未结束，“足”表示血量充足。实际目标还必须满足可达性、风险与现场观察条件。表中是工程策略建议，不是官方战术规定。

| 重装 | 步兵 | 哨兵 | 哨兵任务 |
| --- | --- | --- | --- |
| 足 | 足 | 足 | 维护自己正在守的可达控制区；确认存在其他空缺后再补位，避免无目的巡逻离点 |
| 低 | 足 | 足 | 优先处理重装撤离后**已确认**的地面岗位空缺；若重装仍在位，先考虑批准的侧方掩护岗位，不假装其已撤离 |
| 足 | 低 | 足 | 同理处理步兵撤离后的实际空缺，避免与仍在守点的步兵重复挤入 |
| 低 | 低 | 足 | 优先维持已有可达控制和可行的撤退掩护；不默认深入敌占区，不把满血理解成能独自对抗所有敌人 |
| 足 | 足 | 低 | 哨兵自行恢复；记录需要补位的岗位，但不能等到队友“必然接班”才允许撤离 |
| 低 | 足 | 低 | 哨兵恢复；不能自动给步兵发接替命令；低血两车可以同时有恢复需求 |
| 足 | 低 | 低 | 哨兵恢复；重装血量充足也不等于其正在前来接替，仍需实际观察 |
| 低 | 低 | 低 | 哨兵也恢复，不强制留它送死守点；只有真实通行冲突才协调入口，不能仅凭全队低血制造补给排队 |

当某台已死亡、虚弱或未知时，不能强行归入“低”或“足”。输出中会保留这些区别。两名队友均不可用或状态未知时，哨兵不依据空想的支援去争夺敌占点。

## 血量和位置联合判断

位置反映当前所在区域，不等于意图：

- 低血步兵仍在中央区，不代表它已回家，也不证明它一定会回家。
- 满血重装经过补给区，不代表已承诺接替哨兵。
- 连续看不到队友，或者其坐标过期，不证明控制区为空。
- 队友新鲜位置确实在目标区，可用于避免重复投入；能否接替持守还要有可靠持续驻留/交接证据以及有效血量和非虚弱状态。

因此将任务条件分开记录：控制归属、维护需要、当前哨兵在位、实际队友在位、已确认空缺、已确认交接。`vacancy_confirmed` 必须来自新鲜、明确的区域观察，不能从“没有收到位置”生成；`handover_confirmed` 还需要实际新鲜且血量状态可用的队友在区，单独一个布尔值不能解除哨兵的持守任务。

例：步兵低血但仍占中央点，哨兵可去已批准的附近掩护岗位。待实际观察到步兵撤离、中央岗位存在空缺，才转为补位。如果中央点已有血量充足队友稳定驻留，则避免重复投入；若附近只有一辆短暂路过的车，不据此宣布交接完成。

## 决策顺序

1. 使能、赛项、比赛阶段、有效血量、存活、规则状态和定位门控。
2. 自身虚弱或恢复滞回生效时，选择经验证可达的恢复目标。全队血量情况不取消自身恢复权利，也不会自动提高可接受风险。
3. 血量可用时，优先保持当前确需驻留维护的己方点 `Hold`。
4. 对已确认无人维护且有维护需要的可达己方点，提出补位 `Cover`。
5. 队友有恢复需要时，可选择预先批准且条件成立的地面撤退掩护岗位 `Cover`。
6. 在没有更优先任务时，选择可达、风险可接受的中立/敌占区 `Capture`。队友未知或均不可用时不提出敌占区争夺，中立区也使用更低风险预算。
7. 只有显式配置了巡逻任务，且没有尚未解决的持守责任，才允许 `Patrol`。
8. 缺地图、路线未验证、风险未知或没有合格目标时，输出 `WaitPlan`，说明需要重规划。该状态不表示当前位置安全。

持守责任需要跨帧保存。上一帧守 A，下一份候选列表漏了 A，不能因此忘掉岗位并去巡逻。归属未知、争夺中、交接证据不足时保留责任；可靠确认控制权失去、维护结束或交接完成后才释放。自身低血、战亡、虚弱等恢复/安全条件仍优先，不能被岗位锁困住。

## 地图、路线和风险输入

`TacticalObjective` 包含目标 ID、用途、地形、可达性、规划验证、路线是否经过高地/隧道、预计通行时间、风险及区域证据。全部 XY 坐标需要转换到同一 `map_frame`。

本策略不计算路线，也不把直线距离当成导航可达性。后续适配层需完成地图禁行标注、实际规划验证、坐标系对齐，以及敌情/占用观察。静态地图以版本和配置验证；动态风险、路线占用、控制归属、空缺与交接证据按原始时间过期，不能由高频汇总洗新。

未知风险不能填零。风险数值与预算是工程配置，需要用回放和仿真标定，不能解释成实际死亡概率。即使路线几何上可走，也不能据此保证撤离安全。无可接受恢复路线时应报告并重规划；不能为了执行“低血回家”选一条已知不可接受的路线。

当前策略对普通目标先按任务优先级选择；恢复、掩护和显式巡逻候选内部比较风险，再比较通行时间。尚未实现完整的全局任务评分或最优团队调度。

## 尚需加入的比赛情境

以下因素会改变八种血量组合下的最佳行动，本版尚未全部建模：

- 己方控制度即将归零、剩余时间极短，恢复收益来不及兑现。
- 敌方人数、射界、火力、攻击趋势和队友剩余弹药。
- 返回补给区途中实际碰撞风险、狭窄入口占用、临时障碍和替代撤离路线。
- 控制区独立占领进度、双方同时激活与实际衰减速度。
- 重装装配/发射机构状态对其有效战斗能力的影响。

这些情境需要可靠输入和明确策略后再增加，不能把“满血队友”“低风险分数”当成已经掌握完整战场。射击仍须通过本车弹药、热量、硬件与规则许可检查，队友血量不能覆盖禁射条件。

## 验收场景

至少覆盖八种三车血量组合、恢复中间段、不同最大血量、低血与死亡区分、虚弱、队友过期、坐标非法、已占区重叠、高地/隧道目标、平地目标但禁行穿越路线、全部不可达、风险未知/超预算、守点候选漏项、争夺中保持责任、交接真假、全低血并行恢复，以及缺地图时不生成任务。

本版仍是意图程序：没有接入真实队友位置/血量适配层，没有发送车辆控制命令。已编写的断言用例、ROS 构建与运行记录见 README；未执行的检查不能记为通过。
