# 正常使用时的帧率实测

2026-11-22 15:28:59—15:34:56（北京时间），排除启动前 5 秒，统计
358.43 秒、19,335 帧。使用桌面原入口，海康相机、YOLOv5、控制面板和 C 板 USB
通信同时运行。按用户指定测当前画面；本段没有装甲板检测或目标跟踪帧，结果适用于
这一场景，不能代表目标跟踪负载下的帧率。

## 实测结果

| 环节 | 全段平均 | 每秒统计的最小—最大值 |
| --- | ---: | ---: |
| 相机采集交付 | 65.83 FPS | 64.82—66.76 FPS |
| 视觉处理 | 53.94 FPS | 31.88—64.94 FPS |
| C 板 → 电脑 | 200.01 Hz | 199.05—200.86 Hz |
| 电脑 → C 板 | 72.94 Hz | 68.98—77.53 Hz |

相机每秒计数存在整帧取整误差；相机报告的 `ResultingFrameRate` 为 65.8333 FPS。
视觉每秒帧率的中位数为 54.98 FPS，5% 分位为 40.10 FPS。

海康 SDK 帧号缺口 0，USB CRC 错误 0、无效状态帧 0，处理帧的有效姿态比例 100%。
相机采集快于处理，容量为 1 的最新图像队列主动替换旧图，估算约 18.1% 的交付图像
没有进入处理循环；这与 SDK 帧号缺失、串口丢帧是不同指标。

TX 统计成功写入电脑 USB 驱动的帧数，协议没有逐帧 ACK，因此不能据此证明板端
全部收到。发送线程可重复发送同一视觉结果，发送 Hz 与新目标结果更新 FPS 含义不同。

## 耗时和温度

| 阶段 | 每帧平均耗时 |
| --- | ---: |
| 检测调用 | 13.83 ms |
| 目标处理、面板及相关日志 | 1.56 ms |
| 主循环显示及窗口事件 | 1.98 ms |
| 跟踪调用（本轮无目标） | 0.012 ms |
| 等待可用图像 | 0.004 ms |
| 完整处理循环 | 18.51 ms |

检测调用包括预处理、推理、后处理及检测窗口绘制，13.83 ms 不是纯神经网络推理耗时。
该阶段约占处理循环 75%。本轮没有实际目标，面板阶段数据不能代替有目标时的 MPC 解算耗时。

图像从 SDK 交付到本轮处理结束平均为 25.98 ms；各一秒窗口的 P95 中位数为
33.79 ms。此指标包含最新帧队列等待，不包含曝光、相机到电脑传输、显示扫描或电机响应，
不能解释为完整控制延迟。

额外 90 次在线 CPU 采样中，视觉进程平均占用 303.6% CPU（约 3 个逻辑 CPU，机器共
8 个逻辑 CPU）；CPU 封装温度 76—100°C，平均 94.58°C。另一次 44.06 秒在线观察中，
内核核心/封装热节流累计计数均增加 2,227，证明采样期间发生了热节流。这会影响持续性能，
但现有采样不能把每次帧率下降都单独归因为热节流。

## 提升空间

1. **优先改善持续散热。** 已有热节流证据，先稳定温度，再比较代码优化前后性能，
   避免把温度变化当作算法优化收益。
2. **优化检测和调试绘制。** 目前检测调用约占 75% 的循环时间。可对复用 OpenVINO
   InferRequest、调试窗口降低刷新频率和减少图像拷贝做后续 A/B 实测；本轮没有实施这些
   改动，也没有测出它们各自能提升多少。
3. **修正 USB 发送调度可争取接近设定的 100 Hz。** 代码每次发送结束后执行
   `next_tx = now + 10ms`，随后再次进行最长 5 ms 的 poll 等待；等待和处理开销累计，
   导致实际约 73 Hz。可以按固定时刻推进发送，并依据距离下次发送的时间安排 poll；
   后续修改需验证超时、重连和不能突发补发等行为。本轮发送逻辑未改。
4. **相机当前上限约 65.8 FPS。** 实际曝光为 15,000 µs。相对于本段 53.94 FPS，
   在当前相机参数下追平采集速度约有 22% 的理论余量；这不是已验证的提升承诺。
   想超过当前采集上限，需要调整曝光等采集条件。当前实际增益已为最大值 16.9807 dB，
   请求的 18 dB 设置失败；缩短曝光需实际检查亮度和识别效果，不能只比较 FPS。

本轮新增每秒在线统计和画面叠加，曝光、模型、识别阈值、控制参数和 USB 发送周期均使用
原配置。统计已通过编译、120 帧离线计数校验及上述在线运行验证。桌面程序保持运行，
后续正常使用会继续记录，无需进入单独测速模式。
