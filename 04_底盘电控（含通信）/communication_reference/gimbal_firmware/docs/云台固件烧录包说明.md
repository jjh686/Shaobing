# 云台 C 板固件烧录包

烧录目标：云台 C 板（STM32F407）。本包用于小电脑 USB → 云台 CAN1 → 底盘 CAN2 的通信方案。

## 烧录文件

- EmberProbe 选择：`firmware_release/gimbal_nav_converter.elf`
- 其他支持 Intel HEX 的烧录工具可选：`firmware_release/gimbal_nav_converter.hex`
- 两个文件是同一版本，二选一；EmberProbe 使用 ELF。
- 本版本 CAN1 与底盘 CAN2 均配置为 1 Mbps。

烧录会覆盖云台 C 板当前 Flash 并复位芯片。它只应烧入云台 C 板，不能烧入底盘板。默认电机运动输出仍关闭。

## 文件校验值

```text
ELF SHA-256  abffb6a7dd2e1d47ec5e8eab8cbd39c43f154514d47a91fa9a661d437a4b8bed
HEX SHA-256  010e3c79c5259a6c164389277500754bf072bfe30132fbc4a76ccd146abd4879
```

源码位于当前工作区的 `application/`、`modules/`、`bsp/`、`Src/` 等目录；共享协议维护入口 `common/` 位于上一级工程。本包仅复制已编译文件，不改动编译输入。

`firmware_release/SHA256SUMS` 记录包内 ELF/HEX 的实际校验值。上一级工程执行 `bash tools/build.sh` 后会自动刷新本包；如果只需重新整理已有构建产物，可执行上一级的 `bash tools/package_gimbal.sh`。后续重新编译可能改变哈希，应以包内新生成的 `SHA256SUMS` 为准。

## EmberProbe 配置

当前工程目标为 `stm32f4x.cfg`，调试器脚本为 `cmsis-dap.cfg`，传输 SWD，速度 100 kHz，`.ioc` 为 `basic_framework.ioc`。ELF 位于工作区内部的 `firmware_release/gimbal_nav_converter.elf`，配置读回显示其完整绝对路径，满足 EmberProbe 仅允许访问当前工作区文件的限制。

若侧栏仍提示未选择 ELF，可点击「选择 ELF 固件」，从当前工作区选择 `firmware_release/gimbal_nav_converter.elf`。选中的 ELF 路径和哈希应与本说明一致。实际烧录是否成功，以 EmberProbe 输出的 `Programming Finished`、`Verified OK` 和退出码 0 为准；看到文件已选择或芯片已识别并不等于烧录完成。
