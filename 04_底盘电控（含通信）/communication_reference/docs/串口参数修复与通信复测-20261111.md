# 串口参数报错修复与通信复测

日期：2026-11-11，Asia/Shanghai。

## 报错原因

截图执行 `bash pc/run.sh zero "$PORT"` 后报 `设备不可读写: /home/wangjiaming/桌面/c_board_nav_gateway_20261111`。这是设备参数为空时，旧版 `Path('').resolve()` 将其解析成当前工程目录，随后被字符设备检查拒绝。常见触发方式是在新终端中未重新设置 `PORT`。

此次实际检测到云台应用 USB：`0483:00ca`、产品名 `RM Nav Convert SP`。稳定路径为：

```text
/dev/serial/by-id/usb-YueLuEmbedded_RM_Nav_Convert_SP_315F326E3034-if00
```

本次映射为 `/dev/ttyACM0`。之前的 `/dev/ttyACM1` 是历史编号，插拔和下载器连接情况变化后可重新分配。应优先使用上述 by-id 路径。

## 本次修改

- `pc/check_port.py`：在路径解析前拒绝空字符串及纯空白参数，明确提示 `$PORT` 可能未设置；对目录、非字符设备、访问权限分别报错。仍保留真实 USB VID/PID/产品名校验。
- `docs/烧录成功后通信测试指令.txt`：首条零速测试命令改用完整设备路径，并补充空变量、目录参数的排查方法。
- 没有修改两块 C 板的固件、通信协议、运动锁或导航标定参数，没有进行烧录。

已验证 `zero`、`comm`、`navigation` 三种模式传入空参数都会在打开串口前报明确错误；传入工程目录也会被拒绝。实际设备路径检查通过。
