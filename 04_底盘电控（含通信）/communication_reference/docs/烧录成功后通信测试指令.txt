二、先做 5 秒零速度双向通信测试（推荐第一步）
------------------------------------------------

该测试会：
- 以 50 Hz 从小电脑向云台板发送 STOP；
- 云台板解析后通过云台 CAN1 转给底盘板 CAN2；
- 底盘板回传 ACK、状态和故障信息；
- 检查 ACK 的 session、sequence、uptime 是否连续；
- 全程 ENABLE=0，不发送运动速度。

执行：

cd /home/wangjiaming/桌面/c_board_nav_gateway_20261111
bash pc/run.sh zero "$PORT"

也可以直接使用绝对路径：

bash /home/wangjiaming/桌面/c_board_nav_gateway_20261111/pc/run.sh zero "$PORT"

成功标志：

PASS: ... 帧新鲜底盘 STOP ACK；全程 ENABLE=0。

终端中每行 JSON 反馈的主要字段：
- status：底盘状态位
- fault：底盘故障位
- session：本次通信会话号
- sequence：命令序号
- uptime：底盘运行时间

fault 是可以相加的位掩码：
- 位值 1（LOCK）：默认运动锁，预期结果。
- 位值 2（RC）：遥控器离线或档位未满足。
- 位值 4（MOTOR）：电机反馈不完整，断开电机供电时可能出现。
- 位值 8（UNITS）：轴向/单位未完成实车确认，预期结果。
- 位值 16（RX）：接收队列溢出或排队超时，需要检查通信负载和处理时延。
例如 fault=15 表示 LOCK+RC+MOTOR+UNITS 同时存在。
这些故障位不会否定 USB→CAN→底盘的通信链路；必须重点看是否有持续 ACK 和最后的 PASS。

三、零速度测试失败时的排查顺序
--------------------------------

1. 没有 /dev/serial/by-id/：
   - 检查云台板供电、USB 数据线、BOOT 是否处于正常 Flash 启动；
   - 确认烧录的是 gimbal_nav_converter 固件；
   - 重新拔插云台板自身 USB。

2. 报“设备固件不匹配”：
   - 传入了下载器端口或旧 C 板端口；
   - 重新执行 ls -l /dev/serial/by-id/，选择产品名为 RM Nav Convert SP 的端口。

3. 报“USB 已断开”或“USB 写入超时”：
   - 更换 USB 数据线或电脑 USB 口；
   - 关闭占用该串口的其他程序；
   - 确认只保留一个 ROS/测试进程。

4. USB 能识别但没有新鲜底盘 ACK：
   - 检查两块板是否分别烧录了正确固件；
   - 检查云台 CAN1 对底盘 CAN2 的 H/H、L/L、GND/GND；
   - 检查云台 CAN1 和底盘 CAN2 波特率均为 1 Mbps；
   - 检查 CAN 终端电阻：两个物理末端各一个 120 欧姆；整条总线断电后测 H/L 间通常约 60 欧姆，不能带电测电阻；
   - 确认云台用 CAN1、底盘用 CAN2，且没有把电源脚接到信号线上；
   - 检查底盘板是否已供电、是否已经复位。
