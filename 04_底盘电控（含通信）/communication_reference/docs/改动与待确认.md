## 共享通信代码

| 文件 | 本次用途 |
|---|---|
| `common/protocol.c`、`mcu_link.c`、`gimbal_protocol.c` 及头文件 | 复用新导航 USB 帧、会话/序列/TTL 状态机和关节帧编解码，两块 MCU 与 PC 使用一致格式 |
| `common/nav_can.c/.h` | 新增 3 条命令、3 条反馈 CAN 消息，整组校验、SI→整数转换、顺序/时效/版本验证 |
| `common/nav_gateway.c/.h` | USB 结构解析、route=2 校验、STOP 会话握手、扣除排队和 CAN 时延预算 |
| `common/nav_usb_mux.c/.h` | 同一个 USB 字节流接收原 SP 与新导航完整帧，处理粘包、半包、噪声和 CRC 错误 |
| `common/nav_can_hal.h` | 记录导航组占用的硬件邮箱，组未完成不替换，8ms 超期或 USB 会话复位时请求中止待发帧 |
| `tools/sync_common.py` | 将 common 同步到两板 `modules/nav_conversion`，避免两端协议漂移 |

该实现是解析后重新打包的协议转换：USB 浮点 m/s、rad/s → CAN int16 mm/s、mrad/s → 底盘原电机控制单位。底盘收到全部有效字段后再接收目标；回传 ACK 来自底盘状态机。

## 云台工程改动

- 新增 `application/communication/nav_gateway_port.c/.h`：云台 CAN1 注册、USB/CAN 中断入队、1ms 独立任务、命令转换、真实底盘反馈重新编码为 USB。
- 新增 `nav_joint_config.h`：标定状态明确保持关闭；当前没有可用的已标定关节数据，不能通过改一个宏宣称完成标定。
- 修改 `robot_comm.c`：统一 USB 接收入口分发 SP 与导航，保留原 SP 字段、模式和反馈编码。
- 修改 `application/robot_task.h`、`gimbal.c`：移除关中断初始化期间的阻塞 `INS_Init`；IMU 在低于通信任务的优先级初始化，成功后恢复较高优先级。BMI088 初始化失败不会阻止导航通信任务启动。
- 修改 `gimbal_config.h`：`GIMBAL_INSTALLATION_CONFIRMED` 默认改为 0，用于本次通信联调；云台电机默认停机。保留原自瞄算法和原来的实验 PID，未重新整定云台。
- 修改 USB 启动：提前枚举、在外设初始化阶段真实拉低 D+ 后恢复 USB 功能、移除后来重复的 USB 初始化和无效 DWT 延时；USB 使用 PA11/PA12。
- 修改 USB 产品名为 `RM Nav Convert SP`，VID/PID 仍为 0483:00ca，序列号来自 MCU UID。
- 云台 CAN1 关闭自动重传、打开 bus-off 自动恢复，保留的云台电机通道改为 CAN2；CAN BSP 在复制前校验标准帧、非 RTR、DLC 范围。
- Makefile 加入导航通信源码和 include；原 SP 与云台回归测试适配统一入口，另加默认运动锁测试。

## 底盘工程改动

- 设为 `CHASSIS_BOARD`，只运行底盘任务。板间原 `CANComm` 导航入口替换为 `modules/nav_relay/nav_can_adapter.c`。
- `ChassisTask` 每周期从 CAN 状态机取车体系速度，随后沿用四轮全向运动学、功率控制、电机输出；回传四电机估算的实测速度。
- 保留四个 M3508/C620 的 CAN1 ID：左前 1、右前 2、左后 4、右后 3。初始化即停机，零力分支清参考和斜坡状态。
- 新增默认运动锁与轴向确认锁，只有 RC 双中档、四电机反馈在线、协议和时效正常时才可能放行。CAN 队列溢出/过期进入故障，新的有效 STOP 才清除接收故障。
- 保留此前底盘适配的 SBUS 25 字节长度、头尾、失控/丢帧位验证和 100ms 有效帧时效检查；本次进一步取消非法开关值回退中档，非法值保持 0xFF，不能获得导航授权。
- 保留此前 USART 实际接收长度、CAN 帧类型/长度检查、Linux 编译头文件和链接选项适配。
- 保留此前修正的全向轮逆运动学速度单位，避免平移反馈额外乘一次几何系数。底盘内部旋转量仍由适配层换算，真实物理尺度和正方向必须实测。
- 去除底盘启动对 IMU 的依赖；底盘航向仍由小电脑雷达/定位系统处理。电机离线时不把零值标成有效实测反馈。
- CAN2 同样关闭自动重传、启用 bus-off 自动恢复。原超级电容实例 0x301/0x302 仍保留，与导航预留 ID 不冲突；初次联调需核实总线实际负载和其他设备。

## 电脑端配置

`pc/run.sh` 统一提供四个入口：`preview`、`zero PORT`、`comm PORT`、`navigation PORT`。

- `preview`：新包 ROS USB 节点，connect=false，不打开硬件。
- `zero`：无需 ROS 的 5 秒 STOP 往返检测，独占设备，校验本次固件产品名及新鲜底盘 ACK。
- `comm`：新包 ROS 节点，route=2，50Hz，速度限制 0.3m/s、0.5rad/s，命令超时 150ms，反馈超时 250ms。物理 USB 由节点独占，SP 通过 PTY 代理。
- `navigation`：调用此前配置的新导航完整启动脚本，保留关节角、几何参数与 frame_ready 准入条件。

`pc/source/rm_chassis_comm/firmware`、`方案` 下原有的通用 CAN 示例是包快照的一部分，**没有编入本次 MCU 固件**；实际两板实现以 `common/nav_can.*` 和两个 port/adapter 为准。
