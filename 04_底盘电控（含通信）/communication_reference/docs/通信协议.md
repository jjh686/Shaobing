# 导航 USB 与结构化 CAN 协议 v1

本协议适用于本目录同时构建的两份 C 板固件。USB 沿用已配置新导航包的协议；CAN 是本次新增的结构化整数协议。原 `0x311/0x312` 的 C 结构体通信、此前旧包 A5 透传 `0x320/0x321`，以及新包示例目录中的通用 CAN 分片实现，都不等于此协议。首次接入本协议时，两端都需要兼容实现。仅把云台接口从 CAN2 改为 CAN1，不改变线上字段，底盘原有同版 CAN2 实现继续兼容。

## 物理接口

小电脑 USB → 云台 C 板 → **云台 CAN1 ↔ 底盘 CAN2**。两端均为经典 CAN、1 Mbps。CAN 编号只表示本板控制器，不出现在报文数据中；USB 的 `route=2` 表示经云台转发，不等于指定 CAN2。云台 CAN1 专用于中转，保留的云台电机通道为云台 CAN2，底盘电机继续使用底盘 CAN1。

## USB 命令和底盘反馈

34 字节，整数小端、浮点 IEEE754 binary32。对应代码为 `common/protocol.c`、电脑端 `rm_chassis_comm/src/chassis_node.cpp`。

| 偏移 | 长度 | 命令 0x20 | 反馈 0x21 |
|---|---|---|---|
| 0 | 1 | 0x5A | 0x5A |
| 1 | 1 | 28 | 28 |
| 2 | 1 | 0x20 | 0x21 |
| 3 | 1 | 前 3 字节 CRC8 | 同左 |
| 4 | 4 | PC uptime_ms | 底盘 uptime_ms |
| 8 | 1 | 版本 1 | 版本 1 |
| 9 | 1 | route=2 | route=2 |
| 10 | 2 | sequence | 已接受命令的 sequence |
| 12 | 2 | ttl_ms | status |
| 14 | 2 | flags | fault_mask |
| 16 | 4 | 非零 session | 已接受命令的 session，未接受时可为 0 |
| 20 | 4 | vx，m/s | 实测 vx，m/s |
| 24 | 4 | vy，m/s | 实测 vy，m/s |
| 28 | 4 | wz，rad/s | 实测 wz，rad/s |
| 32 | 2 | 前 32 字节 CRC16 | 同左 |

CRC8：初值 0xFF，右移反射多项式 0x8C，无末尾异或。CRC16：初值 0xFFFF，右移反射多项式 0x8408，无末尾异或，小端存放。

`flags bit0=ENABLE`，其余位必须为零。STOP 要求 ENABLE=0、TTL=0、vx/vy/wz 全零。ENABLE 的 TTL 在本适配中最大 150ms，速度向量不超过 0.3m/s、角速度绝对值不超过 0.5rad/s。电脑配置为 50Hz、150ms 命令超时、250ms 反馈超时。

通用 USB 编解码器允许 TTL 20～250ms；本次网关会进一步缩小范围，并扣除 USB 排队时间和 10ms CAN 预算。剩余 TTL 少于 20ms 的命令不会发送。PC 脚本主动发 ENABLE 时要求原始 TTL 至少 40ms。原包的通用范围不代表本双板固件允许范围。

## CAN 命令：云台板 → 底盘板

标准 11 位 ID，非 RTR，DLC 固定为 8。每组按 0x330→0x331→0x332 顺序发送。

| CAN ID | 字节 0～3 | 字节 4～5 | 字节 6～7 |
|---|---|---|---|
| 0x330 META | session uint32 | sequence uint16 | ttl_ms uint16 |
| 0x331 VELOCITY | vx int16 + vy int16 | wz int16 | 0x0100 \| flags |
| 0x332 COMMIT | PC uptime_ms uint32 | 组 CRC16 | 重复 sequence |

vx/vy 单位 **mm/s**，wz 单位 **mrad/s**，三个字段均为有符号 int16、小端。命令换算向零截断，例如 USB `vx=0.1239m/s` → CAN `123mm/s`；不会因量化增大目标速度向量。命令量化误差每分量小于 0.001 SI 单位。

组 CRC16 覆盖 0x330 的 8 字节、0x331 的 8 字节、0x332 前 4 字节，共 20 字节；CRC 参数同 USB CRC16。最后还核对重复序列号、协议版本、字段范围和会话规则。只有整组有效才交给底盘状态机。

## CAN 反馈：底盘板 → 云台板

每组按 0x338→0x339→0x33A 顺序发送。约 50Hz。

| CAN ID | 字节 0～3 | 字节 4～5 | 字节 6～7 |
|---|---|---|---|
| 0x338 ACK | session uint32 | ACK sequence uint16 | 0x0100 \| status |
| 0x339 MEASURED | 实测 vx int16 + vy int16 | 实测 wz int16 | fault_mask uint16 |
| 0x33A COMMIT | 底盘 uptime_ms uint32 | 组 CRC16 | 重复 ACK sequence |

速度单位同命令，反馈采用四舍五入，误差每分量不超过约 0.0005 SI 单位。CAN 角速度字段范围限制为 ±32.767rad/s；超范围、非有限值或电机离线时清除实测有效位，数值置零表示无有效样本。

组 CRC 同样覆盖前两帧及第三帧前 4 字节。云台验证后重新编码为 USB 0x21；会话、ACK 序列和 uptime 来自底盘。云台收到 USB 或完成 CAN 发送本身都不会产生“底盘执行成功”的 ACK。

### status 位

| 值 | 含义 |
|---|---|
| 0x01 READY | 底盘所有运动准入条件满足 |
| 0x02 ACTIVE | 正在执行未过期的已使能命令 |
| 0x04 ESTOP | 本端急停条件；当前实现包含遥控离线 |
| 0x08 MEASURED | 速度来自在线电机的有效反馈 |
| 0x10 TIMEOUT | 命令有效期超时锁存 |
| 0x20 MANUAL | 导航档位未选中 |
| 0x40 ACK_VALID | session/sequence 确认字段有效 |

### fault_mask 位

| 值 | 含义 | 默认固件说明 |
|---|---|---|
| 0x0001 LOCK | 底盘固件运动开关关闭 | 默认存在 |
| 0x0002 RC | 遥控器离线或双中档未选择 | 随实物状态变化 |
| 0x0004 MOTOR | 四个电机反馈未全部在线 | 随实物状态变化 |
| 0x0008 UNITS | 轴向与单位实测尚未确认 | 默认存在 |
| 0x0010 RX | 接收排队过期或队列溢出 | 新的有效 STOP 可清除 |

## 状态与时效约束

- 新上电、新会话、通信恢复后先发送 STOP，再在底盘 READY/STOP ACK 新鲜且无故障时申请使能。ENABLE 不允许切换 session。
- 16 位 sequence 用模 65536 的前向差判新；差为 0 或大于等于 32768 均拒绝，允许正常回绕。STOP 可移除输出，但重放 STOP 不会解开安全锁存。
- CAN 组接收时间上限 10ms，缺帧、乱序、CRC/字段错误不更新目标。无关 ID 不影响当前组。
- 发送组的软件队列及所属硬件发送邮箱以 8ms 为有效期。禁止替换未完成组；超期请求中止仍待发的邮箱。云台 CAN1 和底盘 CAN2 均关闭无限自动重传并启用自动 bus-off 恢复，避免恢复后排放旧导航帧。
- USB/CAN 中断只复制消息入队；转换在任务上下文执行。底盘用组首帧接收时刻计算 TTL，不用最后一帧到达时刻延长有效期。
- 排队溢出、超时、遥控/电机故障后恢复，不会自动续上之前的速度。

这些时间界限是代码约束，任务调度延迟、实际 CAN 负载和实车停机时间仍需硬件测量。

## SP 与关节数据

USB 同时支持原自瞄 SP 29 字节命令和 43 字节反馈，独立 CRC，收到完整有效帧才分发，避免把数据体里的另一个帧头误识别成新包。电脑节点创建 PTY 代理统一占用物理 USB。

新导航 0x22 关节帧为 46 字节，其格式沿用 `common/gimbal_protocol.c`。本版未拥有底盘相对的真实标定零位，故周期发送的关节诊断帧 `status=0`，PC 会判无效；不会发布可用于 TF 的伪造已标定关节角。

本版本的电控通道传输导航所需的目标速度、实测速度、确认及故障状态。障碍物距离、点云和语义标签仍由小电脑的感知/规划处理；本次未新增这些原始数据的 USB/CAN 字段。若后续电控确需这些字段，需要定义真实数据源、有效期和新的消息版本，不能直接扩写 C 结构体后发送。
