# 双板通信固件生成与烧录（2026-11-20）

本次按 04 目录自带的配套工程生成两个固件：底盘为
`chassis_driver/basic_framework`，云台为
`communication_reference/gimbal_firmware`。不是仓库另一个 `05_云台` 工程，
也不使用旧参考 `communication_reference/chassis_firmware` 的固件。

链路：小电脑 USB ↔ 云台 C 板 CAN1 ↔ 底盘 C 板 CAN2；底盘 CAN1 接四个 C620/M3508。
两端标准 CAN、1 Mbps、每组 3 帧、每帧 8 字节。
命令 ID 为 0x330～0x332，反馈为 0x338～0x33A，遥控为 0x340～0x342。
USB 配置 115200、route=2；route 不表示本板 CAN 编号。

## 本次配置和修复

- 底盘使用 CHASSIS_BOARD，板间通信始终使用 hcan2；现有命令、反馈入口已启用。
- 配套云台由 ONE_BOARD 改为 GIMBAL_BOARD；保留 USB 解析、1 ms 通信任务、CAN1 中转、UART3 S.BUS 接收和遥控转发。
- 底盘 CAN 发送存活窗口由 20 ms 恢复为 8 ms，与配套云台一致，小于 10 ms 接收组帧窗口。
- USB 重连模拟补齐真实 CDC Init/DeInit 中已经存在的网关重置回调；不为测试放宽固件门控。
- 补充 tools/build_gimbal.sh 与 tools/package_dual_board.py。旧路径 CMake 缓存已保存在 build/chassis-before-dual-board-*，新固件从当前路径构建。

底盘运动宏 CHASSIS_COMM_ALLOW_MOTION/CHASSIS_COMM_AXES_VERIFIED 保持现有值 1，
方向保持 VX=+1、VY=-1、WZ=-1。遥控、四电机在线、STOP/session/sequence、TTL、CRC 和队列保护仍生效。
云台 GIMBAL_INSTALLATION_CONFIRMED=0，关节标定有效位仍为 0；本次启用板间通信，不宣称完成云台执行器或机械标定。

## 分板烧录与接线

| 目标实物板 | 应选固件 | 接口 |
|---|---|---|
| 底盘 C 板 | DiPan_Board.elf（或同名 HEX/BIN） | CAN2 接云台，CAN1 接电机 |
| 云台 C 板 | Gimbal_USB_CAN1.elf（或同名 HEX/BIN） | USB 接电脑，CAN1 接底盘 |

两个固件不能互换。用 SWD 分别烧写、校验、复位；ELF/HEX 自动携带地址，BIN 地址为 0x08000000。
USB 接云台不能自动更新底盘。本次未连接下载器、未访问/烧录任何实物。

首次烧录断开电机主电源，保留开发板正常供电。CANH 对 CANH、CANL 对 CANL，共地，
确认总线两端各有一个 120Ω 终端，已有电阻不要重复并联；勿把接口电源针接入 CAN 信号。
遥控接收机 S.BUS 接云台 DBUS；不需要在底盘再接第二个接收机。

## 烧录后验收

停止其他占用 USB 的程序，在小电脑运行：

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/04_底盘电控（含通信）'
ls -l /dev/serial/by-id/
# 按实际云台应用设备修改，不选择 CMSIS-DAP 下载器。
PORT='/dev/serial/by-id/usb-YueLuEmbedded_RM_Nav_Convert_SP_315E326D3034-if00'

bash tools/zero_test.sh "$PORT" --duration 10
```

PASS 表示收到持续的新鲜底盘 STOP ACK，证明 USB/CAN 命令与反馈往返；不代表轮子已获许可。
fault 是位掩码：2=遥控或导航许可问题，4=四电机未全部在线，6=两者同时存在。
电机断电时可能出现 4；历史间歇遥控 fault=2 尚未通过本次软件构建得到实物解决。

运动前四轮架空、四电机在线、CH10 非下档；上电或故障恢复后先让 CH7 或 CH8 离开中档，
再把二者都置中档。fault 稳定为 0 后才做 0.05 m/s、1 秒方向测试。
本次软件验证不替代 CAN 接线、遥控稳定性、轮向、速度比例和断线恢复实测。
