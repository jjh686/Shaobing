# 双 C 板通信实测与修改记录

日期：2026-11-14（北京时间）。目录：`/home/wangjiaming/桌面/DiPan_Board`。

## 结论

本轮已通过实物通信验收：小电脑 USB → 云台 C 板 CAN1 → 底盘 C 板 CAN2 → 云台 USB → 小电脑。10 秒连续发送禁用状态的 STOP，收到 **500 帧新鲜底盘 ACK**。不需要接雷达。

确认的问题是：底盘板内程序与本目录的配套底盘 ELF 不一致。只读 Flash 比对在 `0x08000004` 首次出现差异，累计超过 128 处。烧入配套底盘固件并自动校验后，原有接线下通信恢复。不能把此前错误地址读出的 SRAM 数值当作底盘程序运行证据。

## 测试证据

修复前 5 秒测试：收到 54,543 字节、1,001 帧 SP、250 帧云台导航状态、0 帧底盘反馈。云台状态中的会话及序号与本轮命令匹配；SWD 读取显示 `nav_usb_received=449`、`nav_can_groups=449`、`nav_feedback_received=0`、`nav_gateway_drops=0`。其中 CAN 组计数仅表示提交发送流程，不等于硬件已成功送达。

修复后 10 秒测试：发送 458 条 STOP，收到 500 帧底盘反馈，全部通过会话、已发送序号、ACK 标记和连续新鲜度检查。反馈频率独立于命令频率，因此 ACK 帧数可以高于发送命令数；验收没有要求一帧回复对应一条新命令，但要求底盘 uptime 持续递增。

底盘 SWD 最终计数：

| 项目 | 读数 |
| --- | ---: |
| `chassis_comm_rx_frames` | 1374 |
| `chassis_comm_accepted_commands` | 458 |
| `chassis_comm_decode_errors` | 0 |
| `chassis_comm_rx_overruns` | 0 |
| `chassis_comm_can_esr` | 0 |

CAN 原始帧数 `1374 = 458 × 3`，与三帧命令分组一致。反馈 `status=100`、`fault=15`、速度全零。`fault=15` 包含运动锁、遥控门控、电机离线及轴/单位未标定；本次没有取消这些门控，也没有要求遥控或电机在线才能回复 STOP。

## 代码修改

1. `communication_reference/pc/usb_protocol.py`：保留原底盘反馈解析接口，增加 USB 字节、SP/云台/底盘帧计数及云台命令会话信息。
2. `communication_reference/pc/zero_test.py`、`tools/zero_test.sh`：增加分段诊断、JSON 报告和 1～60 秒时长参数；云台状态不会冒充底盘 ACK。
3. 底盘 `modules/chassis_comm/chassis_comm_port.c`：增加 CAN ESR/TSR 的只读 SRAM 镜像、任务 tick 和反馈组数，供 SWD 区分任务未运行、总线错误和协议错误。此版本已烧入底盘。
4. 云台 `application/communication/nav_gateway_port.c`：同样增加 CAN 镜像、原始接收帧数和解码错误数；已构建，未烧入云台。
5. `tests/test_usb_diagnostic.py`：PTY 对接真实 STOP 检查器，覆盖正常 ACK、只有云台回传、错误会话 ACK，以及分片/损坏帧四项场景；同时确认测试命令始终禁用且速度为零。
6. `tools/test.sh` 统一运行原有通信测试与上述四项；主机编译用显式宏跳过真实 MCU 寄存器镜像，ARM 固件保留镜像。
7. EmberProbe 绑定现有 STM32F407 SVD，分别识别两板 UID。此配置只用于调试，不改变线缆通信。

CAN ID、字段、速率和接线方式未变：命令 `0x330/331/332`，反馈 `0x338/339/33A`，标准数据帧、DLC=8、1 Mbps，导航三帧仍统一使用 FIFO0。底盘 `CHASSIS_COMM_ALLOW_MOTION=0`、`CHASSIS_COMM_AXES_VERIFIED=0`。

构建及验证：两份 ARM 固件编译成功；6 个主机通信测试程序、旧 FIFO 缺陷对照回归及 4 个 Python/PTY 场景通过。构建记录和日志保存在 `artifacts/build_config.json`、`logs/tests-20261114.log`。旧固件与脚本已分别备份至 `logs/firmware-before-diagnostic-20261114.tar.gz`、`logs/usb-test-before-20261114.tar.gz`。
