# USB 识别修复与完整测试指令（2026-11-21）

## 本次报错原因和修复

`05_云台/Src/usbd_desc.c` 使用 `0483:00ca / Vision Comm port`，旧电脑脚本却只接受
`0483:00ca / RM Nav Convert SP`，因此在发送 STOP 前被拦截。
`communication_reference/pc/check_port.py` 现已支持这两个明确的云台应用标识，
继续拒绝 CMSIS-DAP、错误 VID/PID、未知产品、普通文件和非 USB 串口。
产品名只用于选端口，实际导航协议仍由本轮 session、序号、新鲜度和底盘 STOP ACK 验证。

本次仅修改电脑端脚本，无需因为这次名称报错重新编译或烧录固件。
当前两板固件位置见 [分板固件与工程归属](../../05_云台/docs/通信稳定性修复与工程归属-20261120.md)。

用户截图中的设备：

- 云台应用 USB：`/dev/serial/by-id/usb-YueLuEmbedded_Vision_Comm_port_315E326D3034-if00`，本次检查指向 `/dev/ttyACM1`。
- `usb-muselab-tech.com_CMSIS-DAP-...` 是下载器，不用于以下通信测试。

优先使用 by-id 名称，重新插拔后 `ttyACM` 编号可能变化。板内仍需是支持双板导航通信的配套程序；
名称相同的旧视觉固件如果没有导航功能，会在 STOP ACK 测试阶段失败。

## 1. 选择端口并验证往返链路（终端 B）

小电脑 USB 接云台，云台 CAN1 ↔ 底盘 CAN2，底盘 CAN1 接四个电调；两板和遥控接收机正常供电。
先架空四轮。关闭其他占用云台应用串口的串口助手、视觉程序和测试进程。

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/04_底盘电控（含通信）'
export PORT='/dev/serial/by-id/usb-YueLuEmbedded_Vision_Comm_port_315E326D3034-if00'
ls -l /dev/serial/by-id/
python3 communication_reference/pc/check_port.py "$PORT"
bash tools/zero_test.sh "$PORT" --duration 10
```

端口检查应打印实际 `/dev/ttyACM*`。STOP 测试应输出 `PASS` 和新鲜底盘 STOP ACK 数，
报告保存在 `logs/zero-test-last.json`。需要逐帧显示时，另一次执行：

```bash
bash tools/zero_test.sh "$PORT" --duration 10 --verbose
```

STOP 的 PASS 只证明停止命令及反馈往返；运动前还需 `fault=0`。
导航许可要求 CH7、CH8 都中档，CH10 非下档，四电机全部在线。
上电或真实故障恢复后，先让 CH7 或 CH8 离开中档，再回到两者都中档。

| fault 位 | 含义 |
| --- | --- |
| 1 | 编译运动锁 |
| 2 | 遥控离线或导航档未授权 |
| 4 | 四电机未全部在线 |
| 8 | 坐标/单位配置锁 |
| 16 | 接收队列溢出或命令排队超过限制 |

这些位按位或组合，例如 `6=2+4`。电机断电或未授权时不能要求 `fault=0`。

## 2. 先做不依赖雷达的架空前进测试（终端 B）

完成上述 STOP 测试并满足运动许可后，保持四轮架空，执行一次：

```bash
bash tools/motor_test.sh "$PORT" --wheels-raised --direction forward --speed 0.05 --duration 1
```

程序先发送 1 秒 STOP 预检，再发送 1 秒低速前进，最后发送 0.6 秒 STOP 确认。
核对轮向和停车，结果见 `logs/motor-test-last.json`。只有确认四轮架空后才使用 `--wheels-raised`。
如需其他方向，每次单独执行并现场检查，可用 `back / left / right / ccw / cw`；
平移 speed 单位 m/s，旋转为 rad/s。不要同时运行多个串口测试。

## 3. 启动 MID-360 驱动（终端 A，保持运行）

给 MID-360 供电并接入雷达网线；默认雷达 IP 为 `192.168.1.106`，对应小电脑有线网卡须配置
`192.168.1.50/24`。本次查看网络时尚无这个本机地址，需先在系统网络设置中给连接雷达的网卡配置它。
如果使用其他地址，以下两个参数必须与实际配置一致；脚本不会修改网卡。

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/04_底盘电控（含通信）'
ip -br -4 addr
bash tools/lidar_link_test.sh driver --host-ip 192.168.1.50 --lidar-ip 192.168.1.106
```

当前电脑已有构建好的雷达驱动。若更换电脑、清理了缓存或提示未构建，先运行一次再启动 driver：

```bash
bash tools/lidar_link_test.sh build
bash tools/lidar_link_test.sh driver --host-ip 192.168.1.50 --lidar-ip 192.168.1.106
```

保持终端 A 运行；不要同时启动另一份 Livox 驱动占用相同 UDP 端口。

## 4. 确认实时点云（终端 B）

如果重新打开了终端 B，先重新设置工作目录和 PORT：

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/04_底盘电控（含通信）'
export PORT='/dev/serial/by-id/usb-YueLuEmbedded_Vision_Comm_port_315E326D3034-if00'
bash tools/lidar_link_test.sh observe
```

应等待连续 5 帧有效点云，再连续观察 5 秒并输出 `PASS`。
话题为 `/lidar_link_test/livox/lidar`，报告为 `logs/lidar-link-observe-last.json`。

## 5. 实时点云触发一次前进（终端 B）

架空测试已确认方向及停车，遥控许可和电机在线状态正常，终端 A 的雷达驱动继续运行。
先架空验证链路；落地测试时留出前进和惯性滑行空间。先执行一次：

```bash
bash tools/lidar_link_test.sh move --port "$PORT" --speed 0.05 --duration 1
```

程序要求持续实时点云，先完成 STOP/遥控/电机预检，再以前向 0.05 m/s 运动 1 秒，
最后确认 STOP；理想位移约 5 cm。成功要求同时收到底盘 ACK、非零前向轮速和 STOP 确认。
报告为 `logs/lidar-link-move-last.json`。

点云中断、旧时间戳、遥控撤权、ACK 丢失或 Ctrl+C 都会结束本次测试并尝试 STOP，
点云恢复后不会自动续动。STOP 未确认时使用遥控 CH10 下档或切断电机主电源。
这是点云触发底盘自身前进的链路测试，未实现随云台转动雷达的避障或目标点导航。
