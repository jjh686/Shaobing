## 接线与测试前准备

```text
小电脑USB → 云台C板自身Micro-USB
             云台CAN1 H/L ↔ 底盘CAN2 H/L（两板共地）
             云台DBUS ← 接收机S.BUS
                           底盘CAN1 H/L ↔ 四个C620 ↔ 四个M3508
```

接线调整前断电。C620需有正常电机主电源；USB只给板子供电，不能代替电机电源。

| 车头朝前时的轮位 | C620 ID | 反馈标准ID |
|---|---|---|
| 左前 LF | 1 | 0x201 |
| 右前 RF | 2 | 0x202 |
| 左后 LB | 4 | 0x204 |
| 右后 RB | 3 | 0x203 |

四个C620 ID不能重复，均接底盘CAN1；板间通信接底盘CAN2。当前代码必须四个电机均有新鲜反馈才允许输出。云台板需支持遥控CAN转发；本轮已读到真实转发数据，因此没有重刷云台。以后替换云台固件时，不能使用不含0x340～0x342遥控转发的历史USB中转版。

先停止占用该USB串口的导航/通信节点，再单独运行以下脚本。无需启动ROS、雷达、建图或规划；本脚本直接测试整条USB/CAN/电机命令链路。不要同时运行多个控制程序。

## 实际操作顺序

1. 保持四轮架空、轮子附近无人接触，准备好能立即断开的电机电源开关。
2. 打开遥控器并确认接收机在线；CH10不能处于下档。先将CH7或CH8拨离中档，再把CH7和CH8都拨回中档。上电、停止或失控恢复后，都需要重新执行这一步；摇杆没有手动驾驶功能。
3. 给四个C620上电。在同一个终端执行下方环境设置和STOP检查。
4. 确认持续收到新鲜ACK，最后 `fault=0`，`status=73`（READY、MEASURED、ACK）。仅出现PASS而fault非0仍不能运动。
5. 先执行一次前进方向的1秒低速测试，逐轮观察；结束后确认STOP。方向异常、轮子抖动或只有部分轮子动，立即断电，先核对轮序和电机反馈。
6. 前进测试正确后再逐条测试后退、左右平移、旋转。全部方向和停止验证通过后，才能准备落地调参和导航。

环境设置与零速度检查：

```bash
cd /home/wangjiaming/桌面/DiPan_Board
PORT=/dev/serial/by-id/usb-YueLuEmbedded_RM_Nav_Convert_SP_3668306E3533-if00
bash tools/zero_test.sh "$PORT" --duration 5
```

前进测试：默认0.05m/s、仅1秒，指令期TTL=100ms，每20ms发送一次。脚本先STOP握手1秒，只有新鲜底盘ACK持续确认无故障、遥控许可和电机反馈有效，才发送ENABLE。结束或Ctrl+C后尝试发送0.6秒STOP并核对底盘回复；脚本无法替代电机断电开关。

```bash
bash tools/motor_test.sh "$PORT" --wheels-raised --direction forward --duration 1
```

每条命令单独执行、观察停止后再执行下一条：

```bash
bash tools/motor_test.sh "$PORT" --wheels-raised --direction back --duration 1
bash tools/motor_test.sh "$PORT" --wheels-raised --direction left --duration 1
bash tools/motor_test.sh "$PORT" --wheels-raised --direction right --duration 1
bash tools/motor_test.sh "$PORT" --wheels-raised --direction ccw --duration 1
bash tools/motor_test.sh "$PORT" --wheels-raised --direction cw --duration 1
```

`left/right` 目标采用ROS坐标（+Y向左），`ccw/cw`是从上方看的逆/顺时针目标；实际方向尚待机械安装验证，不能凭宏名保证正确。`--wheels-raised`是操作者确认参数，脚本无法检测是否架空。脚本硬限时0.2～2秒，平移不超过0.1m/s，旋转不超过0.2rad/s；默认旋转0.1rad/s。

主动STOP：正在运行测试时按Ctrl+C，待脚本退出后可执行：

```bash
bash tools/zero_test.sh "$PORT" --duration 2
```

异常时优先断开电机主电源。CH10下档、CH7/8退出导航档或遥控失联会撤销软件许可；恢复后需重新切档及建立STOP握手。TTL到期会撤销输出；零力STOP可能让轮子惯性滑行，不表示机械刹停。脚本被强制杀死、电脑死机或USB物理断开时不能保证STOP帧到达。

## 观察结果与排查

| 结果 | 含义/处理 |
|---|---|
| STOP检查PASS、fault=0、status=73 | 链路及固件门控允许进行短时运动测试 |
| fault包含2 | 遥控/导航许可未满足；检查云台接收机、CH10档位，CH7/8先退出再重新进入中档 |
| fault包含4 | 四个电机未全在线；检查C620主电源、ID1/2/4/3、底盘CAN1和H/L |
| fault包含1或8 | 底盘运动宏仍被锁定，确认烧入本记录ELF |
| fault包含16 | CAN接收异常；先修复线缆、队列或组包问题，再用STOP恢复 |
| STOP ACK缺失 | USB/CAN整链路未通过；检查云台USB、两板供电及云台CAN1→底盘CAN2 |
| 电机脚本PASS | 底盘确认接受短时命令并返回STOP；轮子是否按正确方向转动仍需现场观察 |

当前速度反馈由四轮编码器运动学反解得到，不能独立证明机械方向、轮径和减速比正确。默认几何：轴距350mm、轮距300mm、轮半径60mm、减速比19。各轮正负号需按实际安装检查，不能把四轮全都朝同一个视觉方向旋转视为正确。

可通过当前ELF观察底盘 `dbg_ref_lf/rf/lb/rb` 和 `dbg_spd_lf/rf/lb/rb`；它们为电机转子角速度（度/秒）。代码目标符号按LF/RF/LB/RB顺序：前进 `+ - + -`，左移 `+ + - -`，逆时针 `+ + + +`；这些是编码器数值符号，机械观察方向取决于安装。
