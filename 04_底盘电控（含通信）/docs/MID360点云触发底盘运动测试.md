# MID-360 点云触发底盘运动测试

2026-11-21：已修复 05 云台 `Vision Comm port` 被旧电脑脚本拒绝的问题，
当前端口选择、STOP、架空运动和雷达测试完整命令见
[USB 识别修复与完整测试指令](USB识别修复与完整测试指令-20261121.md)。

此入口验证：MID-360 → 网线 → 小电脑实时点云 → USB → 云台 CAN1 → 底盘 CAN2 → 电机及轮速反馈。
它用持续有效点云作为单次前进的条件，速度以底盘自身坐标表示，不用雷达朝向判断障碍，不提供避障或目标点导航。
雷达可安装在云台上；本测试不把点的位置变换到底盘坐标，因此不依赖尚未标定的云台关节。正式导航仍需补齐关节反馈、转轴与雷达外参。

使用已通过通信测试的双板固件即可，无需重新烧录。每次运动默认 0.05 m/s、1 秒，理想位移约 5 cm；参数最多允许 0.05 m/s、2 秒。
先架空四轮核对转向和停车；落地时留出前进及惯性滑行空间。遥控急停仍有效。

## 1. 构建当前仓库的雷达驱动（每台电脑首次运行一次）

所有终端先进入下面目录：

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/04_底盘电控（含通信）'
bash tools/lidar_link_test.sh build
```

脚本直接构建仓库 `02_导航（含通信）/外部依赖源码/livox_ros_driver2`，默认输出到 `~/.cache/rm_lidar_link_test`。
不使用旧桌面导航工程及其 `/tmp` 别名。需要 ROS 2 Humble、colcon 和驱动的编译依赖；当前电脑已完成该构建。
可用 `RM_LIDAR_TEST_RUNTIME` 更换输出目录，后续每个终端使用同一个值。

## 2. 接线与启动雷达（终端 A）

雷达单独供电，网线接小电脑；云台 C 板应用 USB 接小电脑，云台 CAN1 与底盘 CAN2 保持已验证的接线。
默认配置使用小电脑雷达网卡 `192.168.1.50/24`、雷达 `192.168.1.106`。这两个值沿用仓库配置，需与实物一致。

```bash
ip -br addr
bash tools/lidar_link_test.sh driver --host-ip 192.168.1.50 --lidar-ip 192.168.1.106
```

先通过系统网络设置给雷达有线网卡配置上述地址；脚本不会更改网卡设置。本机未配置指定地址时会直接报错。
若雷达实际 IP 不同，修改 `--lidar-ip`。本测试不需要加载已有地图、Point-LIO、Nav2 或旧 `run_chassis_nav.sh`。
不要同时启动其他 Livox 驱动占用相同 UDP 端口。

## 3. 只检查点云（终端 B，不打开底盘 USB）

```bash
bash tools/lidar_link_test.sh observe
```

等待连续 5 帧有效 PointCloud2 后，再观察 5 秒。看到 `PASS` 表示点云持续有效。
默认话题 `/lidar_link_test/livox/lidar`，驱动使用 PointCloud2 格式；原有导航驱动可能使用另一种消息类型或话题，不应混用。
检查包括：原始时间戳、接收间隔、递增时间戳、消息布局、frame_id、抽样 XYZ 的有限非零点数。

## 4. 单次点云触发前进（终端 B）

确认遥控器 CH7、CH8 均为中位，CH10 未急停，四电机正常在线。
若遥控器刚发生故障，先退出导航档，再重新进入；保持之前通信成功时的档位配置。

```bash
ls -l /dev/serial/by-id/
export PORT='/dev/serial/by-id/usb-YueLuEmbedded_Vision_Comm_port_315E326D3034-if00'
bash tools/lidar_link_test.sh move --port "$PORT"
```

将 `PORT` 换成实际云台应用 USB；脚本核对 USB VID/PID/产品名，接受当前 05 的 `Vision Comm port`
和旧配套的 `RM Nav Convert SP`，拒绝 CMSIS-DAP 等调试器。USB 产品名不代替实际底盘 ACK 验证。
关闭其他正在使用该应用串口的通信节点、串口助手和测试程序。
可显式缩短测试：

```bash
bash tools/lidar_link_test.sh move --port "$PORT" --speed 0.03 --duration 0.5
```

过程为：连续有效点云 → 1 秒 STOP/遥控/电机/ACK 预检 → 单次前进 → 0.6 秒 STOP 确认。
点云接收或原始时间戳超过 150 ms、数据无效、遥控许可撤销、ACK 丢失、Ctrl+C 都会结束本次运动并尝试发送 STOP；不会自动恢复运动。
命令 TTL 为 100 ms。150 ms 是点云判失阈值，车辆的物理停车还受传输和惯性影响。
程序不会取消固件的遥控、四电机、会话、ACK 或超时检查。

成功时输出 `PASS`，且必须看到非零前向轮速和 STOP 确认。只有 ACK 而没有前向轮速会报告失败。
若 STOP 未确认，使用遥控急停或切断电机电源。
报告分别保存为 `logs/lidar-link-observe-last.json`、`logs/lidar-link-move-last.json`。
架空测试中的轮速不能证明落地位移，应现场核对方向。

## 5. 软件回归验证

```bash
ROS_LOCALHOST_ONLY=1 ROS_DOMAIN_ID=219 bash tools/lidar_link_test.sh test
```

测试使用合成 ROS 点云和 PTY 模拟底盘，覆盖正常运动、点云中断后恢复不重启、持续收到旧点云、遥控故障、ACK 丢失、Ctrl+C，以及有 ACK 却无轮速。
这些结果属于软件验证；实物 `observe`、`move` 的报告才用于确认当前接线和传感器。
