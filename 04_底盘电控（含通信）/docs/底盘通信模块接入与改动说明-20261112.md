## 2. 硬件与数据路径

```text
电脑导航速度（m/s、rad/s）
  → USB CDC：34 字节协议命令
  → 云台 C 板：解析、校验、重新打包
  → 云台 CAN1 ↔ 底盘 CAN2：三帧一组的导航协议
  → chassis_comm：会话/序号/超时/安全门
  → port：SI 速度换成原底盘内部 aps 参考
  → 原四轮全向运动学、PID、功率控制
  → 底盘 CAN1：四个 C620 / M3508

轮速 → 原驱动速度估计 → SI 反馈 → 底盘 CAN2
     → 云台 CAN1 → USB → 电脑
```

板间使用 1 Mbps 标准 CAN 数据帧，H 对 H、L 对 L、公共地连接；核对实物接口标识，不能把接口电源脚当信号脚。终端电阻按整条总线实际拓扑配置。本次未测量实物接线、电压、终端或波形。

## 3. 模块结构与应用接入

目录：`chassis_driver/basic_framework/modules/chassis_comm/`。

| 文件/目录 | 作用 |
| --- | --- |
| `chassis_comm.c/.h` | 不依赖 HAL/RTOS 的通信核心，显式实例保存协议和安全状态 |
| `chassis_comm_port.c/.h` | CAN2 接收队列、USART3 遥控安全门、轮速在线判断、底盘单位适配 |
| `chassis_comm_config.h` | 集中配置 CAN/UART、轴符号、周期及运动锁 |
| `protocol/` | USB 字节编码、CAN 三帧组包、MCU 会话/TTL 状态机及 HAL 邮箱辅助 |

底盘应用只接入三处：初始化调用 `ChassisCommPortInit()`，任务前调用 `ChassisCommPortCommand()`，速度估计后调用 `ChassisCommPortFeedback()`。

ISR 只复制接收帧与接收时间；任务顺序处理状态，避免中断和任务同时修改命令状态机。核心接口及迁移方法详见模块 `README.md`。

`chassis_comm_rx_frames`、`chassis_comm_accepted_commands`、`chassis_comm_rx_overruns`、`chassis_comm_decode_errors` 可作为调试器观察变量。`decode_errors` 不是全部丢帧/坏帧总数，部分不完整或 CRC 失败组会在更前的组包层直接拒绝。

## 5. 通信协议与单位

USB 使用已有导航 34 字节帧：SOF=0x5A，命令 0x20，反馈 0x21，route=2；与当前适配后的新导航 `rm_chassis_comm` 配套，不能直接用未经适配的旧 PolarBear 原始二进制协议。

下表字段均小端；三帧顺序完整且在 10 ms 组包窗口内才接收。版本高字节为 0x01。

| CAN ID | 第 0～3 字节 | 第 4～5 字节 | 第 6～7 字节 |
| --- | --- | --- | --- |
| 0x330 命令 | session:uint32 | sequence:uint16 | ttl_ms:uint16 |
| 0x331 命令 | vx:int16、vy:int16 | wz:int16 | version/flags:uint16 |
| 0x332 命令校验 | uptime_ms:uint32 | group CRC16 | sequence:uint16 |
| 0x338 反馈 | session:uint32 | sequence:uint16 | version/status:uint16 |
| 0x339 反馈 | vx:int16、vy:int16 | wz:int16 | fault_mask:uint16 |
| 0x33A 反馈校验 | uptime_ms:uint32 | group CRC16 | sequence:uint16 |

所有帧 DLC=8；CAN 线速度单位 mm/s，角速度 mrad/s，电脑和核心接口使用 m/s、rad/s。命令量化向零取整；反馈四舍五入。组合线速度上限 0.3 m/s、角速度上限 0.5 rad/s、TTL 最大 150 ms；超限命令拒收。反馈周期 20 ms。

CRC 为协议实现中的初值 0xFFFF、反射多项式 0x8408，对前两帧 16 字节及第三帧前四字节计算；重复序号也必须匹配。以 `protocol/nav_can.c` 为实际编码依据。

## 6. 安全状态与当前默认值

- `CHASSIS_COMM_ALLOW_MOTION=0`：运动关闭。
- `CHASSIS_COMM_AXES_VERIFIED=0`：物理轴未确认。
- `CHASSIS_COMM_USE_INS=0`：底盘 IMU 任务关闭；反馈使用轮速估计。
- 上电/新会话/安全条件恢复/TTL 过期后，必须先收到新鲜 STOP，再允许本会话后续 ENABLE；拒绝重复和倒退的序号。
- 遥控接收机必须在底盘 USART3 在线，CH7、CH8 都为 MID 才选择导航。切档/失联只停车，本次未实现摇杆手动驾驶仲裁。
- 四轮均有反馈并在线才允许有效轮速反馈和运动安全条件；不会伪造电机在线。
- RX 队列 16 槽、可用 15 槽，溢出会清空积压并停车；超龄接收进入 RX 故障，需后续新鲜 STOP 恢复。
- CAN HAL 发送辅助只管理所属总线邮箱，组发送超过 8 ms 的过期邮箱会终止，避免陈旧命令继续排队。

fault_mask 按位相加：

| 位值 | 意义 |
| ---: | --- |
| 0x01 / 1 | 运动锁未打开 |
| 0x02 / 2 | 遥控离线或不在导航档 |
| 0x04 / 4 | 电机反馈未全部在线 |
| 0x08 / 8 | 单位/坐标轴确认锁未打开 |
| 0x10 / 16 | 接收积压或队列溢出故障 |

无遥控、无电机且保持默认锁时 fault=15 是可预期状态。STOP ACK 通过表示命令到达底盘且有新鲜回传，不表示已可运动。

## 7. 编译结果与测试证据

| 目标 | 输出 ELF | ELF size（text/data/bss） |
| --- | --- | --- |
| 新模块化底盘 | `artifacts/DiPan_Board.elf` | 72388 / 896 / 76976 字节 |
| 兼容云台 USB/CAN1 | `artifacts/Gimbal_USB_CAN1.elf` | 92684 / 1144 / 78360 字节 |

同目录有 HEX、BIN 与 SHA256 清单。新底盘 BIN 为 73292 B；`text+data` 为 73284 B，`data+bss` 为 77872 B，段对齐会产生少量差异。`.elf` 含调试信息，其磁盘大小不等于单片机 FLASH 占用。构建信息见 `artifacts/build_config.json`。

6 项测试：协议、HAL 邮箱、默认锁核心、默认锁完整链路、主机启用模拟核心、主机启用模拟完整链路。测试直接编译实际核心、port 和复制的云台中转代码，使用 `-Wall -Wextra -Werror` 与 UBSan。两种链路各模拟 10,000 次 USB/CAN 往返，覆盖 STOP/ACK、单位、RC/电机失联、TTL、CRC/序号/会话、队列积压溢出、USB BUSY/断开、tick 回绕等。

启用运动的编译宏仅作用于主机测试可执行文件，不用于 ARM 固件。测试结果见 `logs/host-test-results.json`。

另有 FIFO 对照回归：两端都改回旧 AUTO 策略的临时主机反例无法通过 STOP ACK 断言；修复版完成 10,000 次模拟往返。脚本为 `tools/test_fifo_regression.py`，记录为 `logs/fifo-regression.json`。测试仅证明所模拟的中断延迟场景，不证明真实 CAN 已通过。

ARM 工程仍有原有警告：chassis 的未使用 wz_aps、robot_cmd 的未使用函数、power_control 未使用变量，以及 BMI088 中未使用变量和 gNormMin/gNormMax 可能未初始化。INS 默认关闭；若后续启用，应先检查对应标定路径。未把本次构建描述为无警告。
