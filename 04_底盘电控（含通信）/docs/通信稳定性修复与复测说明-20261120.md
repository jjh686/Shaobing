## 修复内容

1. **接收时间戳竞争**：云台先复制遥控快照再取当前时间；两端逐个复制队列报文后刷新时间；底盘输出计算再次取当前时间。消除中断跨过 1 ms 时，无符号减法把新鲜帧误算成超时的路径。没有通过把异常年龄强制清零来绕过真正的超时。
2. **SBUS 流式接收**：保留跨 DMA/IDLE 回调的半帧，支持连续多帧；错误候选帧滑动到下一帧头重新解析。短回调本身不再等同于坏帧。未完成帧跨回调间隔超过 20 ms 时丢弃并记录；整体遥控新鲜度仍为 100 ms。
3. **SBUS 校验与诊断**：检查帧尾、保留标志位、丢帧/失控标志和 CH7～CH10 档位。补齐 CH8 无效检查；保存未转换前的 10 路原始值。真实异常继续增加故障代数并撤销许可。
4. **UART 接收间隙**：DMA 与协议解析使用独立缓冲。复制完成后先重挂 DMA，再运行解析，减少解析期间停止接收的窗口。UART 错误中断用计数代替打印，并记录校验、帧、噪声、溢出、DMA 和重挂失败。
5. **CAN 忙时保留新鲜命令**：前一组发送尚未完成时，后续命令保留在队列中等待下次轮询。超过原有 10 ms 新鲜度限制仍丢弃；队列满仍进入原有故障处理。
6. **USB 发送仲裁**：底盘 ACK、SP、关节遥测分别保留最新一帧，优先级为 ACK > SP > 关节。CDC 忙时由通信任务重试；反馈沿用收到 CAN 的时间戳，入 USB 队列不会重新开始计算 10 ms 期限。USB 断连/复位清理队列。
7. **分类计数**：增加 CAN 硬件错误事件、组包错误、队列过期、任务最大间隔和 USB 发送统计；电脑端区分解析失败与 ACK 筛除原因，并记录最大反馈间隔。STOP 测试默认每 200 ms 打印一次，`--verbose` 可恢复逐帧打印。

线缆协议、CAN ID、1 Mbps 速率、8 ms CAN 发送预算、10 ms 组包限制均保留。05 云台 CAN1 同时服务 yaw，保留其原有电机自动重传及邮箱保护；底盘 CAN2 保持不自动重传。05 整合与验证见 [云台工程归属说明](../../05_云台/docs/通信稳定性修复与工程归属-20261120.md)。

## 保护和重新授权

- 导航许可仍需 CH7、CH8 同为中档；启动或故障恢复后，先让 CH7 或 CH8 离开中档，再都回到中档。
- CH10 下档、真实 SBUS 失控/丢帧、遥控超时、电机离线、命令 TTL 到期仍触发原有保护。
- 许可恢复后仍需本轮 STOP 握手，才能接受 ENABLE。软件不会自动恢复故障前的运动。
- 不应要求未接线、四电机断电或未进入导航档时 `fault=0`。

| fault 位 | 含义 |
| --- | --- |
| 1 | 编译运动锁 |
| 2 | 遥控离线或导航未授权 |
| 4 | 四电机未全部在线 |
| 8 | 坐标/单位配置锁 |
| 16 | 底盘接收队列溢出或命令排队超过 10 ms |

故障位按位或组合。命令 TTL 超时使用 `status` 的 TIMEOUT 位，不等于 `fault=16`。

## 接线后的复测

先架空四轮，给两板和接收机供电，选择正确的云台应用 USB 设备。四电机在线并完成拨杆重新授权后，先做只发 STOP 的检查：

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/04_底盘电控（含通信）'
bash tools/zero_test.sh '/dev/serial/by-id/实际云台USB设备名' --duration 10
```

查看 `logs/zero-test-last.json`：`ack_diagnostics` 给出收到数、通过数和各类筛除数；`stream_diagnostics` 给出 CRC、字段和重同步统计；最大间隔用于发现停顿。周期反馈与命令并非一一对应，不能直接用“命令数减 ACK 数”计算丢帧率。

STOP 检查和许可稳定后，原有点云链路测试入口继续有效，具体见 [MID-360 点云触发底盘运动测试](MID360点云触发底盘运动测试.md)。点云丢失、ACK 丢失或遥控撤权时仍结束本次测试并发送 STOP。

## 再次出现异常时查看的变量

这些诊断变量已确认存在于本次 ELF，可通过调试器读取；它们没有新增到 USB 线缆协议中。

| 位置/变量 | 用途 |
| --- | --- |
| 云台 `fs_sbus_diag` | `frame_lost/failsafe/bad_tail/bad_flags/partial_timeouts/invalid_switches/uart_errors/timeouts` 分别定位遥控源错误；`raw_channels[6..9]` 为 CH7～CH10 原始值 |
| 云台 `rc_usart_instance` 指向的实例 | `parity_errors/framing_errors/noise_errors/overrun_errors/dma_errors/restart_errors` 定位 UART 收发错误；`rx_short_events` 仅记录短回调，不等于坏 SBUS 帧 |
| 云台 `nav_command_expired/nav_command_invalid/nav_command_busy` | 区分队列过期、命令未获接受和发送忙等待；busy 是重试次数，不是丢帧数 |
| 云台 `nav_feedback_expired/nav_feedback_rx_stats` | 区分反馈过期与组包顺序、CRC、长度错误 |
| 云台 `nav_command_queue_full/nav_feedback_queue_full/nav_task_max_gap_ms` | 队列满与任务调度停顿 |
| 云台 `usb_tx_queue` | 下标 0=底盘反馈、1=SP、2=关节；`queued/sent/replaced/expired` 按类别统计，`busy` 为 CDC 忙重试次数；sent 表示 CDC 接受发送，不等于电脑已经收到 |
| 底盘 `chassis_rc_generation/chassis_rc_diagnostics` | 区分源故障代数变化、CAN 新鲜度超时、排队超时、顺序、解码和序号错误 |
| 底盘 `chassis_command_rx_stats/chassis_command_expired/chassis_remote_expired` | 导航命令组包错误、命令与遥控帧排队超时 |
| 底盘 `chassis_task_max_gap_ms/chassis_rx_max_age_ms/chassis_rx_queue_high_water/chassis_comm_rx_overruns` | 调度最大间隔、最长排队时间、队列占用峰值与溢出 |
| 云台 `can_bus_diagnostics[0]`；底盘 `can_bus_diagnostics[1]` | 板间 CAN 的 TEC/REC 及峰值、last_error/latched_errors、bus_off_events、fifo0_overruns/fifo1_overruns、tx_errors |

协议错误计数统计解析候选/事件；队列覆盖计数统计旧遥测被新遥测替换；这些都不能直接当作物理丢帧率。可对照两端发送、接收、解码及电脑筛选统计逐段定位。

## 离线验证

- 11 个主机 C 可执行测试通过，包含两种运动宏配置各 10,000 次实际通信端口模拟往返。
- 跨 1 ms 中断、时钟回绕、新鲜帧与真正 11 ms 过期帧均有回归检查。
- SBUS 全部 24 种拆分点、连续帧、错位重同步、UART 错误、失控/丢帧和无效 CH8 通过。
- 实际 UART BSP 的先重挂后解析、独立缓冲和错误分类通过；实际 USB BSP 的 BUSY 重试、优先级、原始时间戳期限和断连清理通过。
- CAN FIFO 正反回归 2 项、USB 诊断 5 项、电机 PTY 7 项、雷达 ROS/PTY 13 项通过。
- 云台原通信测试两种 API 各 7 组通过；两份 ARM 固件编译通过。
