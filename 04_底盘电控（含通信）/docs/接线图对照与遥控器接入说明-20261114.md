# DiPan_Board 与接线图对照（2026-11-14）

> 历史检查记录：此后已加入遥控CAN转发，最新状态见《遥控CAN转发与接线说明-20261114.md》。下文“尚未转发”等描述仅对应修改前版本。

## 结论和本次修改

现有目录有遥控器代码，但此前云台默认 GIMBAL_AUTO_AIM_ON_BOOT=1，RobotCMDInit 不初始化 SBUS；不能因为有 remote_control.c 就认定遥控器已在运行。
本次修改 RobotCMDInit，使自主/非自主模式都调用 FS_RemoteControlInit(&huart3)，保留自主模式原控制流程。同步更新 gimbal_config.h 注释。
新云台固件：release/云台SBUS接收版-20261114/Gimbal_USB_CAN1_SBUS.elf（另附 HEX/BIN、SHA256SUMS）。烧录对象仅云台 C 板；BIN 起始地址 0x08000000。
该版本已编译，尚未烧录、未做接收机硬件测试。遥控接收加入同一 ELF，不需要另烧一份遥控程序。既有 release/实物通信通过版-20261114 保持原样。

**本次只开启云台本地接收，尚无遥控器 CAN 转发；不能据此宣布图中整车功能已实现。** 自主分支不以遥控器作为控制门控，不可视为遥控急停已接通。所有执行机构仍保持原禁用设置。

## 逐项对照

| 项目 | 图中 | 当前源码/固件 | 结论 |
|---|---|---|---|
| 上位机连接 | USB_OTG_FS 虚拟串口到云台 | USB CDC，导航协议与原 SP 通道复用 | 物理连接相同；上位机必须用本套协议 |
| 板间物理链路 | 云台 CAN1 → 底盘 CAN2，经滑环 | 云台 hcan1 → 底盘 hcan2 | 相同；代码无法确认实车是否经过滑环 |

| 接收机位置 | 仅接云台 UART3（DBUS口），标注 SBUS | 本次开启云台 UART3 SBUS；底盘也在 UART3 初始化自己的 SBUS 接收，并用它判定遥控在线/导航档位 | 关键不一致：只接云台不会使底盘遥控门控通过 |

| 遥控格式 | 图写 SBUS、接口写 DBUS | FS_RemoteControlInit 使用25字节SBUS；不是18字节DJI DBUS | 必须确认实物接收机输出格式和反相条件 |

| 云台 Yaw | CAN1 上GM6020 ID1/反馈0x205，与板间总线共用 | 现有 GimbalInit 将Yaw GM6020 ID1放在CAN2；Pitch也按GM6020 ID2初始化 | 不同，不能直接按图接电机期待运行 |
| Pitch/摩擦轮/拨弹 | CAN2上DM-J4310、3508×2、2006 | 当前云台控制初始化并非这组配置；RobotInit/RobotTask中ShootInit/ShootTask未运行 | 不同，不是图中的完整云台/发射固件 |
| 底盘电机 | 底盘CAN1，M3508×4，ID1/2/4/3 | CAN1；左前1、右前2、左后4、右后3 | 接口/ID对应；实际轮序、方向、尺寸仍须实测 |
| 裁判系统 | 底盘UART6 | UITaskInit(&huart6) | 接口一致，未做本次硬件验证 |
| 超级电容 | 底盘CAN2，0x301/302 | hcan2 TX0x302/RX0x301 | 一致；与新导航ID不冲突，尚未硬件验证 |

## 要实现完全按图运行还缺什么

1. 扩展两端CAN协议：遥控通道、导航许可、急停/失控状态、序号、新鲜度超时，不能只转发一个在线布尔值。
2. 底盘切换为校验云台转来的遥控数据，并处理掉线、重连与命令仲裁；目前仍读本地UART3。
3. 明确人工摇杆控制、导航档位和接管优先级；当前门控不等于完整手动驾驶功能。
4. 云台Yaw迁回CAN1，按真实DM电机型号/模式和摩擦轮、拨弹配置CAN2，另行完成机构标定。通信中转不需要开启这些执行机构。
5. 接收机型号、SBUS输出/反相、停止位、通道映射尚未实测；底盘当前导航判断是CH7与CH8均中档，云台原遥控分支使用的通道定义并不完全相同，需要统一。
6. 电机方向、轮径、减速比、底盘几何和遥控急停验证通过后，才单独解除运动锁、重新构建烧录并架空低速测试。

## 已有证据及本次验证边界

此前实物已通过PC USB→云台CAN1→底盘CAN2的禁用STOP测试：458条命令、500条新鲜反馈。该结果不证明遥控器、云台/发射、电机运动或导航通过。
本次仅修改云台SBUS初始化并构建新映像；未改变底盘固件、未烧录任何板、未发送运动命令。新增映像需要接收机实际数据验证后才能认定接收正常。
