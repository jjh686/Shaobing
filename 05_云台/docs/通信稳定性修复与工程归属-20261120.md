根目录 `AGENTS.md` 已记录后续修改的目录归属。

## 合入内容

- 在 `modules/chassis_link` 合入快照后重新取时间、逐帧刷新队列时间及 CAN 忙时保留新鲜命令的修复。
- 合入 SBUS 流式组帧、错位恢复、CH8 等档位校验，以及 UART 独立 DMA 缓冲、先重挂后解析和错误分类计数。
- 合入 USB 按 ACK > SP > 关节的有界发送队列、CDC 忙重试及原始反馈时间戳期限。
- 合入 CAN 组包和硬件分类诊断；CAN1 SCE 由 CAN BSP 的诊断服务注册和处理，未修改 CubeMX 生成文件。
- 05 的上电自瞄流程原本跳过 SBUS 初始化。现在板间模块单独初始化共用 SBUS 服务，重复调用不会再次注册 UART/守护进程；底盘许可仍来自真实遥控器。

保留 05 原有云台电机、俯仰控制、自瞄参数、CAN 邮箱所有权保护及 USB 断开时继续排空 CAN 的行为。
迁移前后 54 个控制、电机、主入口和配置文件的 SHA-256 一致，记录在
`logs/通信迁移前控制文件哈希.json`。

云台 CAN1 同时服务 yaw，保持 05 现有的电机自动重传；底盘板间 CAN2 保持原来的不自动重传配置。
两端导航发送预算仍为 8 ms、组包/排队新鲜度仍为 10 ms，遥控新鲜度仍为 100 ms。
真实 SBUS 丢帧、失控、超时、CH10 停止和底盘重新拨档授权要求仍生效。

## 编译与发布

在仓库根目录执行：

```bash
python3 '04_底盘电控（含通信）/tools/test_host.py'
python3 '04_底盘电控（含通信）/tools/test_fifo_regression.py'
python3 '05_云台/tools/test_host.py'
bash '05_云台/tools/build.sh'
python3 '04_底盘电控（含通信）/tools/package_dual_board.py' --target gimbal
```

云台中间产物为 `05_云台/build/`，可用固件为 `05_云台/artifacts/Gimbal_ChassisLink.{elf,hex,bin}`，
版本快照为 `05_云台/release/`。04 的 `tools/build_gimbal.sh` 仅转调此构建入口，
不再编译旧副本或向 04 写入新的云台固件。
双板打包器从两份工程分别读取构建清单；默认打包两板，`--target gimbal` 仅发布云台。

## 离线验证与实物复测

05 原有云台/俯仰/电机/USB 通信测试通过；CAN 兼容性 7 个可执行测试通过，
包含真实 05 模块与 04 底盘端口在两种运动宏配置下各 10,000 次模拟往返。
04 跨板测试的云台输入已改为真实 05 源码，11 个主机 C 测试及 FIFO 正反回归均通过。
新加检查覆盖 SBUS 只初始化一次、自动自瞄配置下板间模块仍初始化 SBUS、CAN SCE 和错误计数。
ARM 编译通过，ELF/HEX/BIN 内容一致，源码与固件哈希随包保存。

实物先运行 04 的 `tools/zero_test.sh`；档位和电机条件满足后再运行原有点云触发测试。
计数含义、fault 位和命令见
[通信稳定性修复与复测说明](../../04_底盘电控（含通信）/docs/通信稳定性修复与复测说明-20261120.md)。
