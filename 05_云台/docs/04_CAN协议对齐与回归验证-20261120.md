## 对比结论

比较的04云台源码是 `04_DiPan_Board/communication_reference/gimbal_firmware`，
配套实际底盘源码是 `04_DiPan_Board/chassis_driver/basic_framework`。
05原来已经接入USB/CAN中转，线协议格式一致，但发送时限和异常处理不完全一致。
现已将板间发送时限对齐为04的8 ms，并补齐接收校验和邮箱保护。

| 项目 | 04云台 | 05修改前 | 05修改后 |
|---|---|---|---|
| 接线、速率 | 云台CAN1 PD0/PD1 ↔ 底盘CAN2 PB5/PB6，1 Mbps | 相同 | 相同 |
| 报文类型 | 标准数据帧，每帧8字节，每组三帧 | 相同 | 相同 |
| 导航命令ID | 0x330、0x331、0x332 | 相同 | 相同 |
| 底盘反馈ID | 0x338、0x339、0x33A | 相同 | 相同 |
| 遥控状态ID | 0x340、0x341、0x342 | 相同 | 相同 |
| 编码 | 小端；速度有符号16位，线速度m/s、角速度rad/s，量化乘1000 | 相同 | 相同 |
| 分组校验 | CRC16初值0xFFFF、反射多项式0x8408、序号封口 | 相同 | 相同 |
| 协议版本、会话、序号、STOP和TTL | 导航版本0x0100、遥控版本1；最大TTL 150 ms | 相同 | 相同 |
| 三帧组包窗口 | 10 ms | 10 ms | 10 ms |
| 发送时限 | 8 ms | 20 ms | **8 ms**；沿用04的`elapsed > 8`到期判定 |
| 遥控周期、源年龄门控 | 20 ms周期，100 ms新鲜度，故障恢复后重新拨档 | 相同 | 相同 |
| 反馈FIFO | 三帧统一FIFO0 | 相同 | 相同 |
| BSP接收校验 | 拒绝扩展帧、远程帧、DLC超过8的帧 | 缺少校验 | 已补齐；DLC不等于8的板间帧仍由组包器拒绝 |
| CAN1自动bus-off恢复 | 开启 | 关闭 | **开启**，并同步CubeMX配置 |
| CAN1自动重发 | 关闭 | 开启 | **保留开启**，用于兼容共享CAN1的yaw电机 |
| CAN2控制器配置 | 自动恢复开启、自动重发关闭 | 自动恢复关闭、自动重发开启 | 保留05原值，避免改变pitch/发射电机总线行为 |
| 发送取消与邮箱复用 | 保留待完成邮箱掩码 | reset立即清掩码 | 异步取消期间保留掩码；每次邮箱复用撤销旧所有权 |

导航命令字段依次为会话、序号、TTL；vx/vy/wz、版本及flags；uptime、CRC、重复序号。
反馈字段依次为会话、序号、版本及status；vx/vy/wz、fault mask；uptime、CRC、重复序号。
遥控格式与04的`remote_can.h`完全相同，保留六轴、四拨杆、失控/急停、序号、故障代数和源年龄。

## 为保持05功能而保留的实现

05的yaw GM6020与板间通信共用CAN1，pitch DM4310使用CAN2。因此没有整体替换04工程，
也没有照搬04的全局禁用自动重发设置。线协议、分组规则与时限一致；电机总线的
全局重发策略仍存在上表所列差异，不能称为两份CAN驱动完全相同。

导航与遥控发送超时只取消各自仍拥有的邮箱。实际BSP电机队列复用邮箱时通知网关，
先撤销旧导航所有权，防止超时处理误取消yaw新指令。装载和取消操作使用短临界区，
最多装载三个硬件邮箱，没有等待总线空闲的循环。

以下生产源码逐文件SHA-256与修改前一致：

- `application/gimbal/`、`modules/motor/`：PID、速度PI、pitch assistance、DM4310和电机驱动。
- `application/cmd/`、`application/vision/`、`application/shoot/`：限位、接管、启动自瞄与发射控制。
- `application/communication/robot_comm.c/h`、`modules/master_machine/`：SP 29/43字节协议、原Vision兼容接口和5 ms姿态回传。
- `bsp/usb/`及`Src/usbd_cdc_if.c`：USB会话通知、发送缓冲与SP优先行为。
- `modules/remote/`及任务创建源码：SBUS映射、故障代数、调度周期。

05原有诊断计数、USB断开时排空CAN反馈、独立于USB的遥控转发均保留。
关节姿态仍未标定，继续不置VALID/CALIBRATED标志，本次未更改该行为。
04的源码、历史固件和用户已有核对文档均未修改。

## 验证方法和结果

从05目录执行：

```sh
sh tests/run_all_host_tests.sh
make -j4 all BUILD_DIR=/tmp/gimbal-can-aligned-build
```

全部主机测试通过，包含：

- 原有14组云台速度PI测试、pitch assistance、DJI控制器路由、DM4310驱动、13组云台适配测试。
- 旧Vision和新RobotComm两套接口各7组通信测试；新增SP/导航粘包、导航分帧及USB会话残帧清理测试。
- 04/05协议相关13个源码/头文件归一化换行后的内容一致性检查（时限行注释除外）。
- 04原协议与遥控用例针对05编解码器运行，覆盖CRC、顺序、版本、DLC、EXT/RTR、量化、源年龄、重复序号及计时回绕。
- 8 ms临界值、异步取消、无空邮箱、HAL装载失败重试、yaw与遥控邮箱复用、CAN2隔离。
- 编译并运行真实05 CAN BSP，验证电机发送队列、中断续发、邮箱所有权通知、FIFO0与异常帧拒收。
- 真实05网关加真实04底盘端口：锁定与允许运动两种配置各10,000次往返，覆盖六方向及反馈符号、遥控失联、CH10急停、重新拨档、TTL、电机离线、队列溢出、USB BUSY及重连。

04的旧链路测试仅切换USB配置状态；本次在临时测试副本补充实际CDC Init/DeInit产生的
NavGatewayReset事件，同时通过RobotComm测试验证零长度回调确实发出该事件。
这是对现有05会话机制的模拟，未修改04原测试或05会话逻辑。

ARM Make构建成功：FLASH 102,764 B，RAM 91,168 B；生成
`/tmp/gimbal-can-aligned-build/basic_framework.elf`及同名BIN/HEX。
本次未覆盖05原`build/`内的旧固件；需要在工程目录运行`make -j4 all`才会更新默认构建目录。
