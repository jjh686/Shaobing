# 云台与底盘 CAN 通讯核对

日期：2026-11-20。只整理报告，未修改或移动代码，未烧录或访问硬件。

## 结论及实际入口

05_云台 的 CAN 中转确实已经接入，能够与 04_底盘电控（含通信）/chassis_driver/basic_framework 的现用 CAN 编解码配合，不能根据旧 README 判断为“未实现”。与桌面 DiPan_Board 的底盘线协议也兼容，但桌面发送超时为 8 ms，现用两端为 20 ms；异常行为不完全相同。

实际路径：

- application/communication/robot_comm.c：唯一 USB 入口，nav_usb_mux 将 SP 自瞄和导航帧分发；RobotCommInit 调用 NavGatewayInit。
- application/robot_task.h：创建独立普通优先级 NavGatewayTask，1 ms 调度。
- application/communication/nav_gateway_port.c：USB 导航命令 → CAN1；UART3 遥控快照 → CAN1；底盘反馈 CAN1 → USB。
- modules/nav_conversion/nav_can.c、remote_can.h：导航/遥控线编码，与现用底盘对应实现一致。
- Makefile 已编入 nav_gateway_port、nav_can、nav_gateway、nav_usb_mux 等模块。

板间是云台 CAN1（PD0/PD1）↔ 底盘 CAN2（PB5/PB6），1 Mbps，标准数据帧 8 字节。命令 0x330～0x332，反馈 0x338～0x33A，遥控 0x340～0x342。两端 ID、字段、单位、CRC、版本、分帧及 FIFO0 接收顺序一致。遥控以 20 ms 周期转发，底盘按包含源年龄的 100 ms 超时判断；不是把旧命令反复转发来续命。

## USB 会话测试差异

原底盘 tests/test_chain.c:104 只改变 USBIsConfigured 返回值模拟断线，并没有发出当前 USB CDC Init/DeInit 的零长度回调，因此在换用 05_云台 的真实 gateway 后，“重新接入直接 ENABLE 应停住”的断言失败。实际 Src/usbd_cdc_if.c 在 CDC_Init_FS、CDC_DeInit_FS 调用 rx_cbk(0)，robot_comm.c 再调用 NavGatewayReset，清除导航会话。

在 /tmp 的测试副本补齐这一会话事件后，允许运动模式的 10000 次 USB/CAN 往返和六方向测试通过。原测试失败应记录为“模拟事件与当前架构不一致”；本次证据不支持直接认定真实 USB 重连绕过了 STOP，也不能把补齐事件的模拟当作物理 USB 插拔验收。

## 验证结果

- 云台速度 PI、pitch assistance、DJI hook、DM4310 驱动、云台 adapter 主机测试通过。
- 全套主机脚本在 robot_comm 编译阶段因缺 nav_usb_mux.h 失败。
- make -j4 all BUILD_DIR=/tmp/can-audit-gimbal-build 成功，FLASH 102576 B、RAM 91168 B；只生成 /tmp 构建产物，没有烧录。
- 当前云台真实 gateway 与底盘真实 port：锁定模式 10000 次往返通过；允许运动模式在补齐 USB 会话事件的 /tmp 模拟中通过，覆盖六方向符号、反馈、遥控失联、CH10 急停、重新拨档、TTL、队列溢出、USB BUSY/重连。
- 底盘原 protocol、can_hal 两项测试仍按 8 ms 超时，现值 20 ms，断言失败；具体差异见底盘目录 docs/底盘CAN兼容性与DiPan对比-20261120.md。
