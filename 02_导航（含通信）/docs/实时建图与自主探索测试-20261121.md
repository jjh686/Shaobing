# 固定云台：实时建图、避障与自主探索

已新增 `rm_live_nav` 和 `scripts/run_live_exploration.sh`。本轮按用户选择实现“边建图边自主探索未知区域”：MID-360 + 内置 IMU → Point-LIO → 重力水平的底盘姿态/去车体点云 → 二维扫描/SLAM 地图 → 已知自由空间内的边界目标 → Nav2 绕障 → 运动保护节点 → USB 云台 C 板 → CAN → 底盘。

初次启动不使能底盘，也不自动开始探索。安装数据尚未确认，因此**现在可以开始不连接底盘的建图；落地自动行驶需先补齐测量表**。本轮不修改 C 板固件，不需要因新增上位机模块再次烧录。

用户最新选择：**暂时无法确认雷达轴标注，先只测试建图**。本次实际操作执行 A、B、C；D、E 保留为后续步骤，不在当前实物测试中启用。

## B. 连接雷达网络

雷达使用独立供电与网线。下面沿用先前配置：雷达 `192.168.1.106`，电脑 `192.168.1.50/24`；若雷达实际 IP 不同，替换 `lidar_ip`。先识别实际插雷达网线的网口，不要把 Wi-Fi 或 `usb0` 自动当成雷达网口。

```bash
ip -br link
ip -br -4 addr
```

若实际雷达网口还没有 192.168.1.50，可按实际网口名配置临时地址：

```bash
RADAR_IF='替换为实际雷达网口名'
if [[ -d "/sys/class/net/$RADAR_IF" ]]; then
  # 仅对已确认的雷达网口执行；已有此地址时不用再次 add。
  sudo ip link set "$RADAR_IF" up
  sudo ip addr add 192.168.1.50/24 dev "$RADAR_IF"
  ip route get 192.168.1.106
else
  echo '请先填写真实网口名'
fi
```

应显示走实际雷达网口、源地址 192.168.1.50。新的启动入口会检查本机是否存在指定 host_ip；不会替你改网络。ping 是否回应不能替代 ROS 点云/IMU 检查。

终端 2，保持静止初始化并检查：

```bash
cd '/home/wangjiaming/文档/GitHub/RM_11_13/02_导航（含通信）'
source scripts/local_env.sh
ros2 topic echo /live/motion_state
# 点云/里程计/扫描/地图稳定后 Ctrl+C。
ros2 topic echo /diagnostics
# 应为 Ready, disabled，fault_mask=0；Ctrl+C。
ros2 lifecycle get /controller_server

ros2 lifecycle get /bt_navigator
```

三个 Nav2 节点均应 active，底盘尚未使能。先在 RViz 确认地面水平、底盘姿态/轴向正确、障碍物方位与实物一致，周围留足空地且有人能立即停止。然后在终端 2 **逐条执行并检查 success**：

```bash
ros2 service call /chassis_comm/set_enabled std_srvs/srv/SetBool '{data: true}'
ros2 service call /motion_gate/set_enabled std_srvs/srv/SetBool '{data: true}'
ros2 topic echo /live/navigation_ready
# 应稳定为 true；Ctrl+C 后才执行下一条，下一条开始自动探索运动。
ros2 service call /frontier_explorer/set_enabled std_srvs/srv/SetBool '{data: true}'
```

底盘开始向安全、已知自由空间中的探索目标移动，Nav2 持续规划并检查碰撞。初始控制器使用带碰撞检查的 Regulated Pure Pursuit，以前进、转弯跟随路径，不使用横移。没有足够宽的安全通路时会停车，因此不能以“应该强行通过窄缝”验收。

观察/保存：

```bash
ros2 topic echo /live/exploration_state
# Ctrl+C 后可检查运动状态或保存。
ros2 topic echo /live/motion_state
# Ctrl+C。
bash scripts/run_live_exploration.sh save
```

停止，按顺序执行：

```bash
ros2 service call /frontier_explorer/set_enabled std_srvs/srv/SetBool '{data: false}'
ros2 service call /motion_gate/set_enabled std_srvs/srv/SetBool '{data: false}'
ros2 service call /chassis_comm/set_enabled std_srvs/srv/SetBool '{data: false}'
```

紧急停止优先使用已验证的遥控停止/电机主电源；软件 STOP 不等于机械制动。正常退出先保存，再在终端 1 Ctrl+C。故障或传感器中断后不会自动继续探索，先查原因，再重建遥控许可、STOP 握手并重新执行使能步骤。

## 保护行为与常见状态

| 状态 | 含义/处理 |
|---|---|
| `Confirm measured mounting...` | 安装/轮廓尚未确认；继续做 mapping 并补测数据 |
| `Radar host IP ... not assigned` | 本机雷达网口未配置 host_ip |
| `stale raw_cloud/odom/scan/map` | 对应数据不新鲜；停车并检查驱动、LIO、时间戳/TF |
| `chassis not READY or fault != 0` | 原有遥控/通信/电机保护未满足；不旁路 fault |
| `near obstacle or no usable scan returns` | 近障或扫描无有效回波；移开障碍后手动重新使能 |
| `chassis pose is tilted` | 底盘水平假设不满足，或安装变换有误 |
| `No safe reachable frontier...` | 测试范围内没有可安全前往的探索目标；不是全场探索完成证明 |
| `Input/communication gate lost...` | 已停止并取消目标，需要检查后手动重启 |

原始点云、位姿、扫描 0.3 s 内需持续更新，地图 3 s 内需更新；底盘通信仍独立要求 250 ms 反馈、150 ms 命令时效和新鲜 frame_ready。新保护只收紧输出，不延长旧保护或忽略 fault。近障保护用整车外轮廓的外接圆另加 0.15 m，窄通道会比较保守。
