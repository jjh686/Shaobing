## 尚未确认的数据

云台 yaw/pitch 转轴位置、编码器固定零位和正方向暂缺，`geometry_confirmed=false`。占位 [0,0,0] 不是实测值，不得直接改 true。静态雷达外参单独确认，因此可以正常发布固定雷达 TF，但不会伪造云台动态 TF。

新包代价地图以 gimbal_yaw_fake 为参考帧；当前录入的是底盘中心轮廓。转轴偏置确认后还需核对轮廓参考原点与方向，不能直接把占位转轴当成底盘中心。

完整新入口同时检查底盘真实 READY/STOP ACK、有效的 46 字节云台关节反馈和 frame_ready。当前缺几何数据时保持禁止运动，通信恢复也不会自动使能。

## 软件预览

终端进入本目录：

```bash
cd '/home/wangjiaming/桌面/rm_nav_source_20261110(zbh)'
bash scripts/run_sentry.sh preview
```

该入口启动新通信节点、坐标桥和已测量的雷达静态 TF，不打开物理 USB、不启动雷达、不启动 Nav2。预期显示几何未确认、enabled=false、frame_ready=false。

整套软件启动检查（不需要雷达或 C 板）：

```bash
bash scripts/check_environment.sh
bash scripts/run_sentry.sh check
```

`check` 启动导航、定位、地形、通信和坐标节点，但不打开 USB、不启动雷达和手柄，也不自动激活 Nav2 生命周期。此时地图服务器/控制器等显示 `unconfigured` 是预期状态，用来检查程序和参数能否加载，不代表导航就绪。环境检查结果保存到 `local/environment-check.json`，软件缺项和待连接硬件分开列出。

另开终端记录运行状态：


结果保存到 `local/runtime-observation.json`，包含话题接收频率、时间戳、地图尺寸、TF、诊断和生命周期状态。该工具只订阅数据和查询状态，不发送速度、目标或使能请求。

另开终端观察完整入口的诊断：


## 不接 C 板的独立建图

雷达保持本机约定的水平正装、可靠固定。给雷达供电并将网线连接 enp89s0 后：

```bash
bash scripts/run_mapping.sh rviz:=true
```

此入口只启动 MID-360S、Point-LIO、点云转激光扫描、SLAM、地图保存和可选 RViz，不启动底盘通信或云台坐标桥。可以缓慢手动移动固定好雷达的小车/装置，观察点云与地图；静止时只能观察当前位置周围。

另开终端保存当前地图、检查数据：

```bash
bash scripts/run_mapping.sh --save
bash scripts/observe_navigation.sh --namespace '' --duration 15
```

地图存入启动时打印的 `local/maps/年月日_时分秒/`，包含 `map.pcd`、`map.pgm`、`map.yaml` 和 `summary.json`。有点云时每 60 秒和正常 Ctrl+C 退出时也会保存。没有点云不会生成有效地图；只有点云没有二维栅格时，保存服务返回 success=false，并说明已保存的 3D 数据。

这个入口用 Point-LIO 轨迹投影栅格，关闭二维扫描匹配与回环，不保证大范围往返后的闭环精度。正常建图不发布云台占位 TF，也不要求开启 `geometry_confirmed`。最终安装和场地导航精度仍需实测。

仅检查进程能否启动、不接雷达时可用 `bash scripts/run_mapping.sh start_lidar:=false`；没有输入时不会建出真实环境地图。`local/test-artifacts/` 下的 synthetic 文件夹都是软件测试假数据，不能用于车辆导航。

若要检查新导航的雷达、定位和地形节点，同时不接 C 板：

```bash
bash scripts/run_sentry.sh sensors
```

该模式启动雷达并保持 Nav2 生命周期不自动激活。完整新导航仍需要实测云台关节/几何才能建立全部 TF，因此测试雷达能否建图优先使用独立建图入口。

## 以后连接两块 C 板

两块板必须先在各自电控固件中接入配套新协议、HAL/RTOS 队列、安全许可和电机控制。`gimbal_can.c/.h` 分别使用云台和底盘角色；还需 protocol、mcu_link、can_transport 等依赖。全导航还需要云台真实关节采样和 0x22/46B 反馈。这个源码包没有包含完整的可直接烧录电控工程。

CAN 标准 ID 为 0x320/0x321，具体 CAN1/CAN2 接口由电控回调和实物接线决定。不能把原 0x311/0x312 的 CANComm 当成本协议。

小电脑连接云台 C 板自身 USB 数据口，下载器的串口不属于该链路。查看实际端口：

```bash
ls -l /dev/serial/by-id/
```

两端新固件就绪后，仅测试双板底盘协议的禁止使能收发：

```bash
bash scripts/comm_test.sh usb /dev/serial/by-id/实际云台C板设备
```

观察 `bash scripts/watch_comm.sh`。单独测试使用 `/chassis` 命名空间，完整入口使用 `/red_standard_robot1`。两个入口只能选一个运行，不能争用同一 USB。

连同云台关节/坐标桥一起检查：

```bash
bash scripts/run_sentry.sh usb /dev/serial/by-id/实际云台C板设备
```

保持 enabled=false；USB 打开或收到字节不等于底盘有效 ACK。需检查反馈新鲜度、session/sequence、READY、故障和关节标定状态。

几何和固件都完成后，启动完整导航：

```bash
bash scripts/run_sentry.sh navigation /dev/serial/by-id/实际云台C板设备
```

入口默认使用已复制的测试地图；可通过 `map:=... prior_pcd_file:=...` 指定另一组匹配地图。仍不会自动使能。目标场地、轮向/速度尺度、人工接管和急停验收需另行完成。

若云台几何尚未确认，即使请求 `autostart:=true`，本车完整入口也会延后 Nav2 自动激活并打印原因。几何确认和真实 TF 就绪后再重启完整入口；不能用修改 true 代替测量。默认手柄入口关闭，实车接管使用经过验收的遥控/电控仲裁。
