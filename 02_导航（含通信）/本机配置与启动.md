## 本机入口

```bash
cd '/home/wangjiaming/桌面/rm_nav_source_20261110(zbh)'
bash scripts/check_environment.sh --profile chassis
bash scripts/run_chassis_nav.sh check
```

上面是无硬件的软件启动检查。`check` 不启动雷达，因此黄色 `WARN: No accumulated points to process.` 表示定位节点正在等待点云，是本模式的预期提示，不是程序崩溃。观察进程成功启动后按 Ctrl+C 退出。

连接雷达并供电后，用 `bash scripts/run_chassis_nav.sh sensors use_rviz:=true` 检查实际传感器；要生成新地图用 `bash scripts/run_mapping.sh`，两者不要同时运行。

连接雷达和云台板后，先完成 TXT 中的 STOP 通信测试，再运行：

```bash
bash scripts/run_chassis_nav.sh navigation /dev/serial/by-id/usb-YueLuEmbedded_RM_Nav_Convert_SP_315F326E3034-if00 use_rviz:=true
```

默认使用实验室测试地图，换场地须同时指定同批 `map:=... prior_pcd_file:=...`。导航软件启动不代表车会动：电脑默认 `enabled=false`，交付底盘固件仍禁止运动。

## 本机配置

Ubuntu 22.04 / ROS2 Humble；enp89s0 `192.168.1.50/24`，MID-360S `192.168.1.106`。导航配置为 `local/chassis_nav2_params.yaml`；雷达固定外参读取 `local/measured_mounting.yaml`，车体 `base_footprint`。

小电脑应用 USB→云台 CAN1→底盘 CAN2，1Mbps；当前板间 CAN ID 为0x330/331/332与0x338/339/33A。两板电控适配工程与固件在桌面 `c_board_nav_gateway_20261111`。

运行目录 `/home/wangjiaming/.local/share/rm_sentry_nav_20261110`，脚本自动加载环境。旧工程的 Livox 驱动以及桌面 `small_gicp` 仍是运行依赖，应保留。

## 原完整云台方案

`run_sentry.sh`、`local/nav2_params.yaml`、`local/sentry_real.yaml` 供原云台运动坐标方案使用；该方案仍缺关节几何标定。底盘固定雷达模式无需开启 `geometry_confirmed`，也无需伪造云台关节数据。旧说明备份位置见 `local/chassis_nav_backup_location.txt`，本车本阶段使用上方新入口。
